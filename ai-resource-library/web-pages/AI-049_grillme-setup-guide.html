The Problem With Vague Prompts

Most people open Claude Code, type a one-line prompt, and let the agent guess the rest. The agent always guesses confidently. And it almost always builds the wrong thing.

This isn't a model problem. It's a communication problem. There is a gap between what you have in your head and what you've written down. The agent can only work with what you've given it. When the brief is vague, it fills the gaps with assumptions. By the time you see the output, those assumptions are baked in everywhere.

The Core Issue

The most common failure mode in AI-assisted development is misalignment. You think the agent knows what you want. Then you see what it built and it didn't. This is true with human developers and it's true with AI agents.

How GrillMe Works

GrillMe is a Claude Code skill: a short markdown file with instructions. When you invoke it with /grill-me, the agent reads it and follows it exactly. There's no API, no framework, no execution layer. The leverage is entirely in the words.

Here's the full instruction set, everything the skill tells Claude to do:

Interview me relentlessly about every aspect of this plan
until we reach a shared understanding. Walk down each
branch of the design tree, resolving dependencies
between decisions one-by-one.

For each question, provide your recommended answer.
Ask the questions one at a time.

If a question can be answered by exploring the codebase,
explore the codebase instead.

The Three Rules That Make It Work

01
One question at a time, never bundled

Each question gets your full attention. No long lists. No multi-part questions. You answer, then the next one arrives. This forces real decisions, not skimmed approvals.

02
The agent gives its recommended answer first

It doesn't just ask. It tells you what it thinks. You confirm, correct, or expand. This eliminates the lazy "what do you think?" dead-end and moves every question forward.

03
It reads your codebase before asking

If an answer exists in your repo already, it finds it instead of asking you. Questions that a grep command can resolve don't get asked, saving turns and keeping the session focused.

Installing GrillMe in Claude Code

GrillMe lives inside Matt Pocock's public mattpocock/skills repo on GitHub. You install the whole skills collection once and get GrillMe, plus every other skill, immediately.

1
Open Claude Code in your project root

Navigate to the root of the project you want to use GrillMe on. Claude Code reads skills from a .claude/ folder at the root level.

2
Run the one-time setup skill

Open Claude Code and run the setup command. This configures the repo for your issue tracker and workflow preferences.

3
Answer the setup questions

It asks which issue tracker you use (GitHub, Linear, or local files) and how you label tickets. Answer honestly: this tailors the other skills in the repo.

4
You're ready, invoke GrillMe

Describe what you want to build, then type the command. The agent will start asking questions immediately instead of writing code.

Running Your First Session

A GrillMe session runs entirely inside Claude Code. No prep needed. Just describe your build and invoke the skill. The agent takes it from there.

WHAT TO BRING
  • A rough idea of what you want to build
  • Your codebase open (if building on one)
  • 15 to 45 minutes of focused time
  • An open mind about the final shape
WHAT YOU GET OUT
  • A locked, agreed plan with no gaps
  • All design decisions resolved upfront
  • Zero assumptions left in the brief
  • Code that actually matches your intent

The Flow: Four Stages

01 Describe your plan briefly. Tell Claude Code what you want to build: a feature, a component, a system. No need to be exhaustive. The grilling will extract everything else.

02 Invoke /grill-me. Type /grill-me and send. The first question arrives in about ten seconds. Then another. Then another.

03 Answer each question honestly. Confirm the agent's recommended answer, correct it, or expand on it. Each answer shapes the next question. Sessions run 16 to 50 questions. Matt Pocock typically runs sessions of around 45 minutes.

04 The plan is locked. Now the agent builds. Once every branch of the decision tree is resolved, the agent has nothing left to guess. What it writes from this point matches exactly what you have in your head.

When to Use GrillMe (and When to Skip It)

A grilling session adds intentional friction. That friction is the point, but only when the decision is worth the time. Don't run GrillMe on everything.

USE GRILLME WHEN
  • Building something new with design decisions
  • You've described the brief more than once
  • The brief still feels vague to you
  • It's architecture-level or system-level
  • You'd hate to rebuild it from scratch
  • Decisions have dependencies on each other
SKIP IT WHEN
  • Quick factual lookups or one-liners
  • Editing or tweaking existing code
  • Takes under a minute to decide
  • Copy changes or minor text fixes
  • Single-step tasks with one right answer
The Signal

If you've already started prompting and the output keeps coming back wrong, that's the signal. Stop, open a fresh Claude Code session, and run /grill-me before you do anything else.

Turns the current conversation into a full PRD and publishes it to your issue tracker. No interview. It synthesises what you've already discussed.

/prototype

Builds throwaway prototypes (runnable terminal apps or multiple UI variations) to test design decisions before committing.

Test-driven development with a red-green-refactor loop. Keeps the agent writing honest tests before implementation, not tests that rubber-stamp finished code.
