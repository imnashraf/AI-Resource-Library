Chapter 01 · Why The Debate Is Pointless

Every few weeks a new benchmark drops and developer discourse predictably splits in two. One camp points to the eval where Opus beat GPT-5.5. The other counters with a different eval where GPT-5.5 came out ahead. Neither camp is wrong, exactly. But both are answering the wrong question.

Benchmarks measure the same things in the same way. Real codebases are messier: half-documented abstractions, global state that predates anyone on the team, functions that do three things each. The model that handles that best on any given day is not always the one that topped last week's leaderboard.

The more useful question is: what is each model actually good at in practice, and can you get both in the same session?

The answer to the second part is yes. That is what this guide is about.

Where GPT-5.5 Tends To Win
Faster in most real-world testing. Uses noticeably fewer tokens to finish the same coding task. Sharper on terminal-heavy, shell-based workflows.
Where Opus Tends To Win
Holds more context across a large codebase. More methodical on ambiguous instructions. Tends to catch more of what's actually wrong in a review.

The Real Split

GPT-5.5 is faster in most real-world testing. It uses fewer tokens to complete the same task and is sharper on terminal-heavy, shell-based work. If you are running quick iterations, prototyping, or doing routine refactors, its directness is an asset.

Opus is slower but holds more in memory. Give it a 30-file codebase with a subtle bug buried in the interaction between two modules and it will trace the chain more reliably. It also tends to ask better questions when instructions are ambiguous, rather than making a confident wrong assumption.

Neither of these is a knock on the other model. They are just different tools. The decision to run them sequentially, rather than picking one, changes how you work in a meaningful way.

The Core Idea

Claude builds with full codebase context. Codex audits the result cold. Together they cover more surface area than either would alone, and the total token cost is lower than you expect.

Installing Codex CLI

Codex CLI is OpenAI's command-line coding agent. It runs GPT-5.5 locally from your terminal and can handle file reads, edits, and shell commands. If you already use Claude Code, the mental model will feel familiar immediately.

Install it globally with npm:

npm install -g @openai/codex

Then authenticate with your ChatGPT account:

codex login

This opens a browser window and asks you to sign in with the same account as your ChatGPT plan. Once authenticated, run a quick sanity check:

codex --version

You should see a version string printed to the terminal. If the command is not found, check that your npm global bin directory is on your PATH. On macOS and Linux, npm bin -g returns the path; add it to your shell profile and restart your terminal.

Note

Codex CLI is in active development. If the version you install behaves differently from what is described here, check the official Codex CLI changelog on GitHub for breaking changes before filing a bug.

Chapter 03 · Install The skill-codex Plugin

The skill-codex plugin is a free, open-source Claude Code extension that handles the handoff between Claude and Codex. It lives in the Claude Code marketplace and does not require you to write any configuration files or set environment variables manually.

Here is what happens under the hood when you trigger a dual review:

Claude Builds

Reasons about intent, holds the full codebase in context, makes or describes the change.

Codex Reviews

GPT-5.5 audits the diff from scratch, catching logic errors and edge cases with fresh eyes.

You See Both

Codex's take comes straight back into the same Claude Code thread. No context-switching.

Installing From the Marketplace

Open Claude Code and run:

/install skill-codex

Claude will prompt you to confirm. Type yes and it will pull the plugin, verify that Codex CLI is reachable on your PATH, and register the skill in your session. The whole process takes under a minute.

If you prefer to install from source:

git clone https://github.com/briix-tools/skill-codex
cd skill-codex
npm install
claude skill install .

Both paths end in the same place. The source install is useful if you want to audit the code before running it, or if you plan to fork it and customize the review prompt.

Verifying the Link

After installation, ask Claude directly:

Do you have the codex skill available?

Claude will confirm the skill is loaded and report whether Codex CLI is reachable on your machine. If it reports that Codex CLI is not found, the most common cause is that your npm global bin directory is not on the PATH that Claude Code inherits. Add it to your shell profile, then restart Claude Code.

Note

The plugin only calls Codex when you explicitly ask it to. It does not run automatically on file saves, does not background-watch your repo, and does not send your code anywhere except directly to the Codex CLI process on your own machine.

Chapter 04 · Trigger It & Verify

There are no flags to learn and no config files to write. You trigger the dual review in plain English, the same way you give Claude any other instruction.

01

Install Codex CLI and sign in with your ChatGPT plan

02

Add the skill-codex plugin from the marketplace

03

Ask Claude to use Codex the next time you're about to ship something

The Trigger Phrase

The simplest trigger is:

Review this file with Codex before we ship.

Claude reads the file, makes or describes its changes, then passes the diff to Codex CLI. Codex audits it and returns its notes. Both sets of notes appear in your Claude Code thread, labelled clearly.

You can also be more specific about scope:

Use Codex to review the auth middleware for logic errors.

Or focus on a recent set of changes:

Codex, check the last three commits for edge cases we might have missed.

What to Expect

The first call takes a few seconds longer than a single-model review because two sequential model calls are running. After that, you see Claude's summary first, then a clearly labelled section with Codex's notes.

If Codex has nothing to add, it says so. It does not pad the output or generate filler feedback to justify being called.

Tip

Triggering Codex on every small change will slow your flow. Reserve it for meaningful diffs: new features, refactors that touch shared utilities, or anything going into a release branch.

Troubleshooting Common Issues

Troubleshooting

If Claude says the Codex skill is unavailable after installation, restart the Claude Code session. If Codex CLI returns a 401 error, run codex login again. If the review times out, your Codex plan's rate limit may have been hit. Wait a few minutes and retry.

Chapter 05 · Two Models, One Review

The handoff is intentional by design. Claude builds with your codebase in full context. It knows the function names, the naming conventions, the quirks of the architecture. That accumulated context is what makes it good at writing code that fits the existing system.

Codex starts fresh. It sees only the diff and the relevant file. That constraint is also the point. A reviewer who has been staring at the same code for two hours misses things that a fresh read catches immediately. The edge case that was obvious when you wrote the function becomes invisible once you have accepted it as given.

How to Read the Output

After a dual review, you will see two labelled sections in your thread. The first is Claude's output: what it did, why, and any notes on places it was uncertain. The second is the Codex review: specific flags, alternative approaches, and anything it would do differently.

Where they agree, you can move forward with confidence. Where they disagree, you have a real signal worth investigating. The disagreement itself is not a problem to resolve. It is the value you are paying for.

Prompts to Try Tonight

These are worth running the first time you set this up, to get a feel for how the handoff actually behaves:

Build a basic rate limiter for the API routes, then have Codex
review it for bypass scenarios.
Refactor the database connection pooling. Once you're done,
ask Codex if there are any race conditions.
Write unit tests for the payment module. When you have a draft,
use Codex to check for cases that aren't covered.

Start with something you were already planning to ship this week. The goal is not a demo. It is a real second opinion on code that will matter.

On Trusting the Output

Neither model is infallible. Codex will occasionally flag something that is intentional. Claude will occasionally miss an edge case that Codex catches. Your job is not to defer to either model but to use both as inputs to your own judgment.

The pattern that works best is straightforward: Claude for the build, Codex for the adversarial read, you for the final call. That division of labour is more reliable than any single model running solo, and it scales as both models continue to improve.

Why This Matters

Running both models does not double your cost. Most of the token spend is in Claude's build phase. The Codex review is a targeted audit on a diff, which is a small fraction of a full-context call. The improvement in review quality outpaces the added cost by a significant margin.
