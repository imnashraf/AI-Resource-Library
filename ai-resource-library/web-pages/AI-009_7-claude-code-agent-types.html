7 Claude Code Agent Types

Max Johnson @maxjohnscn

Build Agents That Automate Basically Anything Inside Claude Code.

Most people using Claude Code do not know these seven agent types exist. Each one is a different pattern for how an agent can be structured, and each one solves a different class of problem. Master all seven and you can build agents that handle real work, not just demos.

  • The setup pattern for each agent with ready-to-use prompts
  • A framework for combining agent types to tackle complex real-world tasks

Agent Type 01, Basic Agent With Tools, The starting point

Give Claude access to external tools, calendar, Gmail, contacts, and it can plan and execute tasks on its own. This is the foundation every other agent type builds on.

What it does:

  • Accesses connected tools autonomously
  • Plans multi-step tasks without being told each step
  • Executes actions, booking, emailing, updating, without hand-holding
$ Claude Code, basic agent setup

You are an autonomous agent with access to the following tools:
- Calendar: read and create events
- Gmail: read, draft and send emails
- Contacts: search and retrieve contact information
When given a task, plan the steps needed and execute them
using the available tools. Do not ask for confirmation on
each step unless the action is irreversible.

TIP: Start here before building any other agent type. Getting comfortable with tool access and autonomous execution is the foundation everything else relies on.

Agent Type 02, Agent With MCP Servers, This is where it gets powerful

Connect your agent to Notion, Atlassian, databases and any service with an MCP integration. The agent can now read and write to everything you store and manage, not just execute tasks.

What it does:

  • Connects to Notion, Jira, Confluence, databases via MCP
  • Reads existing data before acting, context-aware decisions
  • Writes back to your systems, updates tickets, pages, records
$ Claude Code, add MCP server connection

# Add Notion MCP
claude mcp add notion --api-key YOUR_NOTION_KEY
# Add Atlassian MCP
claude mcp add atlassian --api-key YOUR_ATLASSIAN_KEY
# Verify connections
claude mcp list

NOTE: Each MCP server gives the agent a new domain of access. The more servers connected, the more the agent can see and act on. Start with one and expand.

Agent Type 03, Sequential Agents, An assembly line built from AI

Chain multiple agents together so the output of one becomes the input of the next. Agent 1 reads your contacts, passes the data to Agent 2 which writes the email, Agent 3 sends it. Each agent specialises in one step.

What it does:

  • Breaks complex tasks into specialist steps
  • Each agent receives the previous agent's output as context
  • Errors stay contained, one broken step does not corrupt the whole chain
$ Claude Code, sequential agent chain

# Agent 1, reads and formats contact data
AGENT_1_OUTPUT=$(claude run 'Read contacts matching [criteria].
Return structured JSON with name, email, company.')

# Agent 2, writes personalised email from the data
AGENT_2_OUTPUT=$(echo $AGENT_1_OUTPUT | claude run 'Using
this contact data, write a personalised outreach email.')
# Agent 3, sends the email
echo $AGENT_2_OUTPUT | claude run 'Send this email via Gmail.'

TIP: The key to sequential agents is clean handoffs. Each agent should output something specific and structured that the next agent can consume without ambiguity.

Agent Type 04, Parallel Execution Agents, Multiple agents, one result

Split a task across multiple agents running simultaneously. Agent A does research, Agent B does analysis, Agent C does writing, all at the same time. Results merge at the end. What takes one agent ten minutes takes three agents two.

What it does:

  • Runs multiple specialist agents simultaneously
  • Each agent works on a different aspect of the same goal
  • Results are merged into a single unified output
$ Claude Code, parallel execution pattern

# Launch three agents in parallel
claude run 'Research the market landscape for [topic].
Return key findings as JSON.' &
claude run 'Analyse competitor positioning for [topic].
Return strengths and weaknesses as JSON.' &
claude run 'Write an executive summary for [topic]
using the provided context.' &
# Wait for all to complete then merge
wait

NOTE: Parallel agents work best when the sub-tasks are genuinely independent. If one task depends on another's output, use sequential agents instead.

Agent Type 05, Agents With Routers, The AI traffic controller

Add smart routing logic that directs incoming tasks to different workflows based on the content. Urgent tasks go to the fast track. Sales enquiries go to the CRM workflow. Support requests go to triage. The right task always goes to the right place.

What it does:

  • Reads incoming input and classifies it before acting
  • Routes to different agent workflows based on the classification
  • Handles mixed input streams without manual sorting
$ Claude Code, router agent pattern

You are a routing agent. When you receive a task:
1. Classify it as one of: URGENT, SALES, SUPPORT, GENERAL
2. Route accordingly:
- URGENT: invoke fast-track-agent with priority flag
- SALES: invoke sales-workflow-agent with CRM context
- SUPPORT: invoke support-triage-agent
- GENERAL: invoke standard-agent
Always explain your classification before routing.

TIP: Router agents are most valuable when you are dealing with high volumes of varied input, emails, messages, tickets, where manual sorting is the bottleneck.

Agent Type 06, Human In The Loop, For high stakes tasks

The agent does all the work but stops and waits for your approval before executing. It prepares everything, explains what it is about to do, and only proceeds when you confirm. The right agent for anything irreversible or high risk.

What it does:

  • Completes all preparation and planning autonomously
  • Presents the proposed action clearly before executing
  • Waits for explicit human approval, does not proceed until confirmed
$ Claude Code, human in the loop pattern

You are an agent with human approval required for all actions.
Workflow:
1. Analyse the task and plan every step
2. Present your complete plan in plain English
3. List every action you will take and its consequences
4. Ask: 'Do you approve this plan? Reply YES to proceed.'
5. Only execute after receiving explicit approval
6. If anything changes mid-execution, pause and re-confirm

WARNING: Never skip the approval step for human-in-the-loop agents. The value of this pattern is the human checkpoint, removing it defeats the purpose entirely.

Agent Type 07, Orchestrator Agent, The most powerful agent type

A main agent that dynamically spawns specialist sub-agents on demand. When the orchestrator decides it needs help with a specific part of a task, it creates the right agent for that job in real time. No fixed pipeline, adapts to whatever the task requires.

What it does:

  • Acts as a team lead, breaks complex goals into specialist tasks
  • Spawns sub-agents dynamically based on what each task requires
  • Coordinates sub-agent outputs into a unified result
  • Adapts its team structure based on what the work actually needs
$ Claude Code, orchestrator agent pattern

You are an orchestrator agent. Your job is to break complex
goals into specialist tasks and spawn sub-agents to handle them.
When you receive a goal:
1. Identify the distinct specialist tasks required
2. For each task, spawn a sub-agent with a specific role and
precise instructions
3. Collect and synthesise all sub-agent outputs
4. Deliver a unified final result
Spawn sub-agents using: claude run '[specific instructions]'
You may spawn sub-agents that themselves spawn further agents
if the task requires it.

TIP: The orchestrator pattern has no hard limit on scope. It can spawn agents that spawn agents. Start with simple two-level orchestration, one orchestrator, two or three sub-agents, before going deeper.

Combining All Seven, How to Think About Agent Architecture

These seven types are not mutually exclusive. Real-world agent systems combine multiple patterns. A common pattern for a business automation system:

  • A router agent (Type 5) receives all incoming requests
  • Routes urgent tasks to a human-in-the-loop agent (Type 6)
  • Routes standard tasks to an orchestrator (Type 7) that spawns parallel sub-agents (Type 4)
  • Each sub-agent connects to relevant services via MCP (Type 2)
  • Complex workflows run as sequential chains (Type 3)

TIP: Start with Type 1 and get comfortable. Add MCP connections when you need external data. Use sequential or parallel patterns when a single agent is not enough. Add routing when input volume grows. Add orchestration when tasks become genuinely complex.
