Claude Code + Codex Setup Guide

Max Johnson @maxjohnscn

Two AI Models. One Codebase. Nothing Falls Through.

This guide gets you set up with the skill-codex integration, a free GitHub repo that lets Claude Code delegate tasks directly to OpenAI's Codex CLI. Once it is running, Claude and Codex review the same work from different angles. What one misses, the other catches.

What you will have when this is done:

  • Codex CLI installed and working on your machine
  • The skill-codex plugin installed inside Claude Code
  • Your CLAUDE.md configured with a hook that triggers Codex automatically
  • Two AI models auditing your work on every test, simulation, and review

Before you start. You need three things already in place before following these steps:

  • Claude Code installed and working on your machine
  • An OpenAI account with API access (to use Codex CLI)
  • A GitHub account to download the skill repo

NOTE: The Codex CLI is a separate tool from ChatGPT. It runs locally and calls the OpenAI API directly. You will need an OpenAI API key, find it at platform.openai.com/api-keys.

Step 01, Install the Codex CLI, From OpenAI

The Codex CLI is OpenAI's command line tool. It runs locally on your machine and is what Claude Code will call when it delegates a task to Codex. Install it via npm with the command below.

$ Terminal, install Codex CLI

npm install -g @openai/codex

Once it is installed, authenticate it with your OpenAI API key:

$ Terminal, add your OpenAI API key

export OPENAI_API_KEY=your-api-key-here
# To make this permanent, add the line above to your ~/.zshrc or ~/.bashrc
# then run: source ~/.zshrc

TIP: To check the install worked, run: codex --version in your terminal. If it returns a version number you are good to go.

Step 02, Download the skill-codex Plugin, github.com/klaudworks/skill-codex

This is the GitHub repo that bridges Claude Code and Codex. It contains the skill file that tells Claude Code how to call Codex and what to do with the results. Download it and place it inside your project.

$ Terminal, clone the skill-codex repo

git clone https://github.com/klaudworks/skill-codex.git

Once cloned, copy the plugin folder into your project:

$ Terminal, copy the plugin into your project

cp -r skill-codex/plugins/skill-codex \
./your-project/.claude-plugin/skill-codex

NOTE: Your project folder should now contain a .claude-plugin folder with the skill-codex folder inside it. Claude Code looks for plugins in this location automatically.

TIP: The repo has 868 stars and is actively maintained. If you want updates in future, clone it somewhere permanent and symlink the plugin folder into your projects instead of copying it each time.

Step 03, Add the Hook to Your CLAUDE.md, Tell Claude when to use Codex

This is the step that makes the whole thing automatic. You add a hook to your CLAUDE.md file that tells Claude Code to call Codex whenever it is running tests, auditing code, or simulating behaviour. Claude does its work first, then Codex reviews it from a completely different angle.

Open your CLAUDE.md file (or create one in your project root if it does not exist). Add the following block:

$ CLAUDE.md, add this hook

## Codex Integration Hook
# Uses OpenAI Codex CLI to audit, test and simulate.
# Codex reviews from a different angle, catches what Claude misses.
when: "running tests OR auditing OR simulating"
do:
- run_skill(codex-review, target=current_task)
- compare_outputs(claude_result, codex_result)
- flag_discrepancies(threshold=medium)
- merge_best_solution()

TIP: The hook triggers automatically on any task that involves testing, auditing, or simulation. You do not need to prompt it manually.

WARNING: If you do not have a CLAUDE.md file in your project root, create a new file called CLAUDE.md and paste the block above into it. Claude Code reads this file at the start of every session.

Step 04, Verify It Is Working, Run a test task

Open Claude Code with your project folder selected and ask it to run a test or audit a file. You should see Claude call the Codex skill in its process, it will show the Codex review alongside its own output and flag any discrepancies between the two.

$ Claude Code, paste this to verify the integration

Audit this project for any logic errors or edge cases.
Use the Codex skill to review from a second perspective.
Flag anything that differs between your analysis and Codex's.

TIP: If Claude does not call Codex automatically on the first run, check that the .claude-plugin folder is in the right location and that the CLAUDE.md hook block is formatted correctly with no extra spaces.

How It Works, Two Models. One Review.

Claude Code and Codex are trained differently. They have different strengths and different blind spots. When Claude finishes a piece of work, the hook fires Codex to review the same output from scratch.

Claude is strong at reasoning about intent, understanding context across large codebases, and handling ambiguous instructions. Codex is trained heavily on code execution paths, it is particularly good at spotting logical errors, edge cases, and things that pass tests but break in production.

The result is a combined output that is more reliable than either model working alone. In practice, the number of things that slip through drops noticeably after the first week of running this.

TIP: The most useful trigger is the audit task. Ask Claude to audit a file you are about to ship and the Codex review will consistently surface at least one thing Claude did not flag.
