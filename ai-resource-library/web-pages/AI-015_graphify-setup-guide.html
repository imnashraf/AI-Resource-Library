Chapter 01, What Graphify Actually Does

Every time you send a prompt in Claude Code, Claude reads files to understand your project. With a large codebase, that means re-reading the same files over and over. Every prompt. Every session. That is where the tokens go.

Graphify solves this by mapping your entire codebase once, upfront, into a structured knowledge graph. Instead of reading raw files, Claude reads the map. The map tells it where everything is, what connects to what, and what it needs to look at. So it does not re-read things it already knows.

This is Andrej Karpathy's system. He coined the term vibe coding and is one of the most influential AI engineers working today. The 70x token reduction figure comes from real-world usage of this approach.

Without Graphify

  • Claude reads every file
  • Same files re-read every session
  • Token usage = file sizes

With Graphify

  • Claude queries the map
  • Only reads what's needed
  • Token usage = task complexity
70x token reduction

How it works in three steps:

  1. Graphify maps your project. You run Graphify inside your Claude folder. It reads every file and creates a knowledge graph, a structured index of everything in the codebase, including how files relate to each other.
  2. Obsidian visualises the graph. You open the same folder in Obsidian and turn on graph view. You get a visual map of your entire project, every file, every connection. Optional but useful for understanding what was built.
  3. CLAUDE.md tells Claude to read the map. You add one line to CLAUDE.md. From that point on, every time you open a Claude Code session, Claude reads the map first. It already knows where things are before you type your first prompt.

Chapter 02, Step One: Install Graphify

Graphify is open source, maintained by safishamsi on GitHub. It supports Claude Code, Codex, OpenCode, Cursor, Gemini CLI, GitHub Copilot CLI, VS Code Copilot Chat, Aider, OpenClaw, Factory Droid, Trae, and Google Antigravity. Over 28,000 stars. Requires Python 3.10 or higher.

1 Go to the GitHub repo. Open your browser and go to: https://github.com/safishamsi/graphify

2 Run the install command. Open your Claude Code terminal and run:

pip install graphifyy && graphify install

TIP: Make sure you have Python 3.10+ installed before running this. Type python3 --version in your terminal to check.

3 Run Graphify in your project folder. Navigate to your main Claude project folder in the terminal, then run the Graphify skill. It will read every file in the project and build the knowledge graph.

cd ~/your-project-folder graphify run

NOTE: This may take a few minutes on larger projects. Graphify reads and indexes every file. You only need to run this once, then re-run when your project changes significantly.

Chapter 03, Step Two: Open in Obsidian

Obsidian is a free note-taking app that reads folders of markdown files. Because Graphify outputs markdown, Obsidian can read the graph it has created and display it visually. This step is optional but highly recommended, seeing the full map of your project is useful for both you and for understanding what Graphify has built.

1 Download Obsidian. Go to obsidian.md and download the free desktop app. Available for Mac, Windows, and Linux: https://obsidian.md

2 Open your project folder as a vault. In Obsidian, click Open Folder as Vault and select the same folder you ran Graphify in. Obsidian will read the markdown files Graphify created.

TIP: Open the exact same folder you ran graphify run in. Obsidian needs to see the files Graphify generated.

3 Open Graph View. In the left sidebar, click the graph icon, or press Cmd + G on Mac / Ctrl + G on Windows. Obsidian will display a visual map of your entire codebase, every file as a node, every connection as a line.

What you are looking at is a full index of everything Claude is working with. Clusters of closely connected nodes are areas of high dependency. Isolated nodes are standalone files.

NOTE: The graph view is for your understanding. Claude does not see this visual. What Claude reads is the underlying knowledge graph data that Graphify created.

Chapter 04, Step Three: Update CLAUDE.md

This is the step that actually changes how Claude reads your project. On its own, Graphify creates the knowledge graph. Claude does not know to use it unless you tell it to. The CLAUDE.md file is how you tell it.

CLAUDE.md is a file in the root of your project that Claude Code reads automatically at the start of every session. You are going to add a section that tells Claude to always check the graph first.

THE SNIPPET TO PASTE IN. Open or create a CLAUDE.md file in the root of your project folder. Paste this section in:

## Context Navigation When you need to understand the codebase, docs, or any files in this project: 1. ALWAYS query the knowledge graph first: '/graphify query "your question"' 2. Only read raw files if I explicitly say "read the file" or "look at the raw file" 3. Use 'graphify-out/wiki/index.md' as your navigation entrypoint for browsing structure

TIP: This is the exact snippet from Andrej Karpathy's system. Do not modify the structure, Claude needs these specific instructions to prioritise the graph over raw file reads.

Once this is in your CLAUDE.md, every new Claude Code session opens with these instructions loaded. Claude will query the graph first, not read raw files, unless you specifically tell it to.

What each line does:

  • Line 1 tells Claude to always run a graph query before reading any file. The query returns relevant nodes and relationships, not raw file contents.
  • Line 2 prevents Claude from defaulting back to raw file reads. Without this, it might still read files even when the graph has what it needs.
  • Line 3 sets a navigation entrypoint. When Claude needs to browse the project structure rather than query for something specific, it starts from the index.

Chapter 05, Why This Works

The token reduction comes from a difference in information density. When Claude reads a raw source file, it processes everything in that file, every line of code, every comment, every import, even if only 5% of it is relevant to your prompt. When Claude reads the knowledge graph instead, it gets a compressed, structured summary of what is in the file and how it relates to everything else. The relevant signal, without the noise. That compression is where the 70x figure comes from.

Without Graphify: You send a prompt asking Claude to modify a function → Claude reads the entire source file to find the function → Claude reads imported files to understand dependencies → Claude re-reads the same files it read last session → Token usage scales with file sizes, not task complexity.

With Graphify: You send the same prompt → Claude queries the graph: finds the function, its dependencies, its connections → Claude reads only what is directly relevant → No re-reading. No noise. Just the information it needs → Token usage scales with task complexity, not codebase size.

NOTE: The larger and more complex your project, the more significant the token reduction. On small projects the effect is noticeable. On large codebases it is transformative.
