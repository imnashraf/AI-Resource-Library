Dynamic Workflows in Claude Code

Max Johnson @maxjohnscn

Chapter 01, What Dynamic Workflows Actually Are

Dynamic workflows let Claude Code break a single task into dozens or hundreds of sub-agents that all run at the same time. Instead of Claude working through a task step by step, it writes its own orchestration script, spins up a full network of specialised agents, and runs them in parallel. The chat session stays responsive while everything runs in the background. At the end you get a consolidated report, not a turn-by-turn transcript.

You give Claude one instruction. It figures out the architecture itself.

The feature is currently available in research preview in the Claude Code CLI, Desktop, and VS Code extension for Max, Team, and Enterprise plans, as well as on the Claude API, Amazon Bedrock, Vertex AI, and Microsoft Foundry.

Available on: Claude Code CLI, Claude Code Desktop, VS Code Extension, Claude API, Amazon Bedrock, Vertex AI, Microsoft Foundry. Plans: Max, Team, and Enterprise.

Chapter 02, How It Actually Works

When a workflow kicks off, Claude plans dynamically from your prompt. It breaks the task into subtasks, fans work across sub-agents running in parallel, and agents address the problem from independent angles. Other agents then try to refute those findings. The run iterates until the answers converge.

You give one prompt
Claude reads and plans the architecture
2
Work fans out
Up to 16 parallel agents, up to 1,000 total
3

4
Consolidated report
Final output delivered to you
  1. Claude plans from your prompt. It reads your instruction and breaks the task into subtasks. You don't define the architecture, Claude does.
  2. Work fans out across parallel agents. Sub-agents address the problem from independent angles simultaneously. Up to 16 agents run concurrently, with a cap of 1,000 agents per run.
  3. Agents verify each other's findings. Separate agents attempt to refute the outputs from the build agents. The run iterates until answers converge.
  4. Progress saves and resumes. An interrupted job resumes within the same session. Completed agents return cached results on resume.

WHY THIS HANDLES LARGE TASKS: Intermediate results live inside script variables, not in Claude's context window. That is why workflows can handle tasks that would normally be too large for a single session.

Chapter 03, Two Ways to Start a Workflow

Turn on auto mode first. From there you have two options.

1 Just ask directly. Type something like "Create a workflow for this" and Claude will build the orchestration script and run it. No extra setup required.

2 Switch on ultracode. Accessible through the effort menu. It sets the effort level to extra high and lets Claude decide automatically when to use a workflow to handle your task. If the task is complex enough to warrant parallel agents, Claude will spin them up without you having to ask.

TIP: Ultracode is the hands-off option. If you want control over when workflows run, use the direct ask. If you want Claude to decide, switch on ultracode.

The 750,000 Line Rebuild. A developer generated roughly 750,000 lines of code in eleven days, keeping 99.8% of the existing test suite green. He used dynamic workflows, with hundreds of agents running in parallel. That kind of refactor would normally take a full engineering team several months. The speed came from genuine parallelism, not Claude just working faster on a linear task.

Chapter 04, The Review Layer

This is the part most people miss. The system compares and reconciles outputs from different agents, checking them against each other before producing a final answer. That verification step increases the chances the system will catch inconsistencies before the final result reaches you.

For security audits and bug hunts specifically, Claude searches a repo in parallel and then runs independent verification on every finding, so the report only surfaces real issues.

How to Activate the Review Layer. Add this to your prompt to make sure the review layer runs:

"Once the build agents finish, run a dedicated review pass with agents that had no involvement in the build. Flag anything that needs fixing before you give me the output."

NOTE: Without explicitly requesting a review pass, Claude may skip this step. Add it every time, even on smaller tasks it catches things a linear pass would miss.

Chapter 05, Where This Is Most Useful

Dynamic workflows are built for tasks that are too complex for a single agent: investigating widespread bugs, managing large migrations, conducting security audits, reviewing performance, and analysing the architecture of complex software projects.

Core Use Cases:

  • Investigating widespread bugs, Parallel agents search across a codebase simultaneously, cross-referencing findings before surfacing results.
  • Large migrations, Hundreds of files touched in parallel, with agents working on independent sections simultaneously.
  • Security audits, Auth checks, input validation, and unsafe patterns searched in parallel across an entire codebase.
  • Performance reviews, Codebase-wide profiler-guided optimisation audits run concurrently across all relevant files.
  • Architecture analysis, Complex software projects mapped and analysed from multiple independent angles at once.
  • Large-scale refactors, Hundreds of files touched in parallel, with independent verification before the final output.
  • Multi-part research tasks, One agent reads the codebase, another tests assumptions, another hunts for bugs or inconsistencies, all in parallel.

WHY PARALLEL MATTERS: Doing research in parallel not only provides speed, it lets the system explore more possibilities at once.

Chapter 06, How to Trigger a Dynamic Workflow

Open Claude Code and give it a task that has multiple components. Then tell it explicitly to build a workflow.

Prompt That Works Well:

"Create a dynamic workflow for this. Break it into parallel sub-agents, run them simultaneously, and include a review layer before giving me the final output."

If You Want to See the Plan First:

"Before you run this, show me the workflow structure. List the agents you are going to create and what each one is responsible for."

TIP: Reviewing the plan first is useful when running a large workflow for the first time. You can confirm the structure before any tokens are consumed.

Including the Review Layer (Repeat Every Time):

"Once the build agents finish, run a dedicated review pass with agents that had no involvement in the build. Flag anything that needs fixing before you give me the output."

Chapter 07, Tips for Getting the Best Results

  1. Be specific about the components upfront. The more clearly you define what needs to be built, the more precisely Claude can divide the work between agents. Vague tasks produce vague splits.
  2. Tell it the constraints early. Files it should not touch, dependencies to respect, output format you need. Put those in the initial prompt rather than correcting it afterwards.
  3. Start scoped. Dynamic workflows can consume substantially more tokens than a typical Claude Code session. Anthropic recommends starting on a scoped task to get a feel for usage before running it on something large.
  4. Use the review layer every time. Even on smaller tasks it catches things a linear pass would miss. Add the review layer prompt on every workflow run.

HARD LIMITS: Up to 16 concurrent agents at once. Maximum 1,000 agents total per run. Progress saves as the run proceeds and an interrupted job resumes within the same session.

TOKEN USAGE: Workflows consume substantially more tokens than a typical Claude Code session. Start scoped, understand the cost, then scale up.
