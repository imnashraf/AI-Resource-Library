Part I, Installation & Setup

Before you install a single thing, it's worth taking a moment to understand what you're actually setting up. Openclaw is not a chatbot. It's not a website. It's not something you install and forget about.

Think of it more like bringing on a digital team member and giving them access to your business systems, emails, files, APIs, databases, messaging platforms. That's exactly what makes it powerful. And it's also why getting the setup right from the start matters.

Start With a Dedicated Environment. One of the most common mistakes people make when getting started is jumping straight in on their main machine. If you plan to use Openclaw for any kind of client work or real business workflows, resist that urge.

You want to set this up in an environment that's completely separate from your everyday computer, your personal files, browser sessions, saved passwords, and private accounts should never be in the same space as a running AI agent.

Your main options:

  • A dedicated laptop or desktop used only for this purpose
  • A small home server or Mac Mini
  • A secured VPS (covered in detail below), this is what most people should start with

Using a VPS. A Virtual Private Server (VPS) is a private computer that lives in the cloud and stays online 24/7. It gives you a clean, isolated environment without needing to manage physical hardware, and it's the setup we'd recommend to most people starting out. For getting started, Hostinger is a solid choice.

Why a VPS beats your personal machine:

  • It stays online even when your laptop is closed or turned off
  • You can access and manage it securely from anywhere
  • Your personal files, passwords, and accounts are completely separate
  • Backups, upgrades, and migrations are much simpler to manage
  • It looks and functions like professional infrastructure, not something cobbled together

Setting Up Your Hostinger VPS:

  1. Choose your plan. Head to Hostinger and start with the KVM 1 plan. It's the most affordable option and more than enough to get started. Monthly billing is fine while you're learning.
  2. Select your server location. Pick a location that's geographically close to you.
  3. Choose your operating system. Select Ubuntu 24.04 LTS when prompted. This is the most stable and well-supported option for running Openclaw.
  4. Save your configuration details. After purchase, you'll see a configuration screen with your environment variables. Pay close attention here.

Configuration variables you'll see on setup:

  • OPENCLAW_GATEWAY_TOKEN: Auto-generated. Copy and save this somewhere safe before moving on.
  • ANTHROPIC_API_KEY: Your Anthropic API key for Claude integration. (Optional at this stage.)
  • OPENAI_API_KEY: Your OpenAI API key. (Optional at this stage.)

Once installation completes, Docker will automatically create a project for Openclaw. Your Openclaw instance will be accessible at: http://your-vps-ip:port

Post-Installation Configuration:

Step 1: Connect your Gateway Token. Open the Openclaw web interface and click Overview. Find the Gateway Token field, paste in the OPENCLAW_GATEWAY_TOKEN you saved during setup, and click Connect.

Step 2: Connect a Messaging Channel. Openclaw can connect to Telegram, Discord, WhatsApp, and more. For this walkthrough, we'll connect WhatsApp. Go to Settings > Config and click the RAW button to open the raw configuration editor. Add the following WhatsApp configuration:

"channels": { "whatsapp": { "dmPolicy": "allowlist", "allowFrom": [ "[YOUR-PHONE-NUMBER-HERE]" ], "groupPolicy": "allowlist", "mediaMaxMb": 50, "debounceMs": 0 } },

Make sure your phone number is in international format (for example: +447700900000). Click Apply, then Update. Go to Channels and click Show QR. On your phone, open WhatsApp, go to Settings > Linked Devices, and scan the QR code.

Step 3: Set Your AI Model. In the same RAW configuration editor, add the following to assign a model to your agent:

"agents": { "defaults": { "model": { "primary": "openai/gpt-4o" }, "maxConcurrent": 4, "subagents": { "maxConcurrent": 8 } } },

Adjust the model name to match your preference and API access.

Validating Your Setup. Before connecting any real business tools or client data, run a quick set of sanity checks:

  • Create and modify a file
  • Run a simple research task
  • Draft an email or short document
  • Review the system logs afterwards

Running Openclaw Continuously. For client work and any long-running systems, Openclaw needs to stay running in the background:

openclaw service enable openclaw service start openclaw status

Part II, Security & Hardening

Important: Read this before connecting anything.

Running Openclaw for client work means you are operating production infrastructure. You are responsible for security, uptime, data protection, and in some industries, legal compliance.

Understanding the Risk. Openclaw connects language models to real operational tools. It can read files, send messages, call APIs, and move data between systems. A compromised agent can affect everything it touches. Your goal is controlled failure: if something does go wrong, the damage should be limited, visible, and reversible.

Protecting Your Gateway. By default, your gateway should be bound to 127.0.0.1. This keeps it accessible only inside your private network. Never expose it on 0.0.0.0. If you ever do need to expose the gateway externally, it must be protected by a VPN, strict firewall rules, and IP allowlists. All three, not just one.

Managing Credentials Properly. Three non-negotiable rules:

  • Never store secrets in plaintext files. Use environment variables with restricted permissions.
  • Limit scopes. Each token should only have access to exactly what it needs and nothing more.
  • Isolate credentials. Different clients and different systems get different keys.

Human Oversight: Where to Add Checkpoints:

Action TypeWhen
Read-only actionsAutomatic
Write actions (creating, editing content)Confirm before proceeding
Destructive actions (deleting, overwriting)Manual approval required
Accessing credentials or sensitive dataAlways logged

Monitoring and Operational Habits. Enable and maintain: session logging, error reporting, activity alerts, regular credential rotation, automated backup systems. Review your logs weekly.

Backups and Recovery. Every production Openclaw system needs backups. Enable VPS snapshots in your Hostinger control panel. Set up automatic weekly backups at minimum. Test your restore procedure every quarter.

Pre-Launch Security Checklist: Gateway is private and bound to 127.0.0.1 | Pairing is enforced | All tokens are properly scoped | Environments are isolated | Logging is enabled and working | Backups are in place and tested | Your incident response plan is written down.

Security debt compounds faster than technical debt. The time to fix these things is before you go live, not after.
