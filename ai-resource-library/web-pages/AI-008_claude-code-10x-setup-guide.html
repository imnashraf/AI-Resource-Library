Remote Control, Hooks and App Previews, Three Things Most People Are Not Using.

These three features shipped in the last year and most people building with Claude Code have not set any of them up. Remote control lets you keep building from your phone. Hooks run automatically after every code change so you never have to think about linting or tests. App previews let Claude look at what it built and fix what it sees. Each one on its own changes how you work. All three running together and you are operating at a completely different level.

What you will have when this is done:

  • Remote control active, build from your phone or any browser
  • Hooks configured for linting, code quality and tests on every change
  • App previews enabled, Claude tests its own work visually

Feature 01, Remote Control, /rc, Build from anywhere

Remote control connects your local Claude Code session to any browser or phone. Type /rc in your Claude Code CLI. It creates a secure tunnel, generates a URL, and opens in the Claude Code app on whatever device you point it at. Your code stays on your local machine. You just control it from anywhere.

$ Claude Code CLI, start remote control

/rc
# Claude will output something like:
# Secure tunnel established
# Remote URL: https://rc.claude.ai/s/xxxxxxx
# Open that URL on your phone or any browser.
# The Claude Code app launches automatically if installed.

TIP: This is most useful when you want to keep a long-running task going while you step away from your desk. Start a build, type /rc, send the URL to your phone, and monitor or continue from anywhere.

NOTE: The tunnel is secure and session-specific. Each time you run /rc it generates a new URL. Close the CLI session and the connection ends automatically.

Feature 02, Hooks, Deterministic Automation, Always runs, every time

CLAUDE.md is a suggestion. Claude can read it, partially follow it, or ignore it. Hooks are deterministic, they always run. Add them to your project and they fire automatically on pre-task and post-task events. The three most useful hooks are linting, code quality checks, and running your test suite after every code change.

Add a hooks configuration file to your project:

$ Terminal, create your hooks config

# In your project root, create .claude/hooks.json
mkdir -p .claude
touch .claude/hooks.json

Then add your hooks:

{
 "hooks": {
 "post_tool_use": [
 {
 "matcher": "Write|Edit|MultiEdit",
 "hooks": [
 {
 "type": "command",
 "command": "npm run lint"
 },
 {
 "type": "command",
 "command": "npm run test"
 }
 ]
 }
 ]
 }
}

TIP: The matcher 'Write|Edit|MultiEdit' means the hooks fire whenever Claude writes or edits any file. Adjust the commands to match your stack.

NOTE: You can add as many hooks as you need. Pre-task hooks fire before Claude starts a task. Post-task hooks fire after.

WARNING: Hooks run as shell commands on your machine. Make sure your lint and test commands exit with a non-zero code on failure, that is how Claude knows something went wrong and needs fixing.

Feature 03, App Previews, Claude Tests Its Own Work, Vision, not logs

App previews shipped in Claude Code desktop five days ago. When enabled, Claude starts your dev server, opens an embedded browser, takes screenshots, clicks elements, fills forms, and reads what it sees using vision. It is not reading your console logs, it is actually looking at the rendered output and iterating on what it finds.

App previews are available in Claude Code desktop only. To use them:

  • Open Claude Code desktop (not the CLI)
  • Open your project folder
  • Ask Claude to build or test something, the preview panel opens automatically
  • Claude starts your dev server, opens the browser, and begins visual testing
$ Claude Code desktop, trigger a visual test

Build the hero section and test it visually.
Check that the CTA button is clickable and the form submits correctly.
Fix anything that looks wrong.

TIP: You can click on any element in the preview panel and pass a note directly to Claude. Point at something that looks off and type what you want changed, Claude sees exactly what you are pointing at.

NOTE: App previews work best for web projects with a dev server. Claude will attempt to detect and start your dev server automatically based on your package.json or framework config.

All Three Together, A Different Way of Building

Remote control means you are never blocked by being away from your desk. Hooks mean linting and tests run on every single change without you thinking about them. App previews mean Claude catches visual errors before you do.

Most people building with Claude Code have none of these running. Setting all three up takes about 15 minutes. The difference in how you work after that is not subtle.

TIP: Start with hooks, they have the most immediate impact and take five minutes to configure. Add remote control next time you are working on a long build. App previews are worth switching to Claude Code desktop for any web project.

Claude Code desktop is free to download at claude.ai/download.
