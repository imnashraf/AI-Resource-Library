Chapter 01, What This Actually Does

By default, Claude Code sends every request to Anthropic's API. That's what costs money. Every token goes through their servers, you get a bill at the end of the month, and your code leaves your machine.

This setup replaces Anthropic's API with Ollama, a local engine that runs open-source AI models directly on your computer. Claude Code doesn't change. You don't change how you use it. You just redirect where it sends its requests: from Anthropic's servers to localhost.

The result: zero API costs, no rate limits, and nothing leaves your machine. Everything runs locally.

How It Works. Ollama exposes an API endpoint on your machine that mimics the Anthropic Messages API format. When you set the right environment variables, Claude Code sends its requests to that local endpoint instead. Ollama then runs the model you've pulled and returns the response, entirely on your hardware.

What You Need:

  • Claude Code installed (npm install -g @anthropic-ai/claude-code)
  • Ollama installed (covered in Chapter 02)
  • A compatible local model (covered in Chapter 03)
  • Three environment variables set (covered in Chapter 04)

NOTE: This works on macOS, Windows, and Linux. The commands in this guide use macOS/Linux syntax. Windows users: use the PowerShell equivalents shown in the environment variables chapter.

Chapter 02, Step 1, Install Ollama

Ollama is the local engine that runs AI models on your machine. It installs like any other application, runs in the background, and exposes a local API on port 11434 that Claude Code can talk to.

Download and Install. Go to ollama.com and download the installer for your operating system. On macOS it's a standard .dmg. On Windows it's an .exe installer. On Linux you can run the one-line install:

curl -fsSL https://ollama.com/install.sh | sh

After installing, Ollama starts automatically and runs in the background. On macOS you'll see it in your menu bar. On Windows it runs as a system tray application.

Verify It's Running. Open your browser and go to http://localhost:11434. If Ollama is running correctly, you'll see a plain text response confirming the service is active.

You can also check it from the terminal:

ollama --version

TIP: If you see an error when running ollama commands, the service may not be running yet. On macOS, open Ollama from your Applications folder. On Linux, start it manually with: ollama serve

Chapter 03, Step 2, Pull a Coding Model

With Ollama running, you need to download a model. The model is what actually does the thinking, Ollama is just the engine that runs it. For Claude Code specifically, you want a model with strong tool-calling and coding capabilities.

Powerful Machine, Qwen 3 Coder 30B. If you have at least 16GB of VRAM (GPU) or 32GB of unified/system RAM, run the 30B model. It's a Mixture-of-Experts architecture that runs faster than its size suggests, only 3.3B parameters are active per token, so it behaves more like a 3B model in terms of speed while delivering 30B quality.

ollama pull qwen3-coder:30b

This is the best local coding model available right now. It supports 256K tokens of context natively and has been specifically trained for agentic coding tasks, exactly what Claude Code needs.

HARDWARE: 16GB+ VRAM GPU (RTX 3090, RTX 4090, M1/M2/M3 Pro or Max). Or 32GB+ system RAM for CPU inference (~12 15 tokens/sec at Q4).

Less Powerful Machine, Qwen 2.5 Coder 7B. If you're on a laptop or a machine with less memory, go with the 7B model. It's smaller and faster, and it still handles the core coding tasks Claude Code throws at it.

ollama pull qwen2.5-coder:7b

Needs around 4 5GB of VRAM or 8GB+ of system RAM. Works on most modern laptops.

TIP: Not sure which to use? Start with qwen2.5-coder:7b. If it feels too slow or struggles with larger tasks, upgrade to qwen3-coder:30b.

Confirm the Model Downloaded. After the pull completes, verify the model is available:

ollama list

You should see your model listed with its size.

HEADS UP: The model download can be large, qwen3-coder:30b is around 17GB at Q4 quantisation. Make sure you have enough disk space and a stable connection before pulling it.

Chapter 04, Step 3, Set Environment Variables

This is the only configuration step. Three environment variables tell Claude Code to send its requests to your local Ollama server instead of Anthropic's API.

macOS and Linux. Add these three lines to your shell profile, either ~/.bashrc (Bash) or ~/.zshrc (Zsh):

export ANTHROPIC_BASE_URL="http://localhost:11434" export ANTHROPIC_AUTH_TOKEN="ollama" export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1

After adding them, reload your shell:

source ~/.zshrc # or if you use Bash: source ~/.bashrc

Windows (PowerShell). Add these to your PowerShell profile ($PROFILE):

$env:ANTHROPIC_BASE_URL = "http://localhost:11434" $env:ANTHROPIC_AUTH_TOKEN = "ollama" $env:CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = "1"

What Each Variable Does:

  • ANTHROPIC_BASE_URL, Redirects Claude Code's API requests from Anthropic's servers to your local Ollama instance at port 11434.
  • ANTHROPIC_AUTH_TOKEN, Claude Code expects an auth token. Setting it to 'ollama' satisfies that requirement without needing a real Anthropic API key.
  • CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC, Stops Claude Code from sending telemetry, update checks, and other background requests. Keeps everything local.

Verify the Variables Are Set:

echo $ANTHROPIC_BASE_URL echo $ANTHROPIC_AUTH_TOKEN # Both should print your values

TIP: If you'd rather not add these permanently to your profile, you can set them temporarily for a single session by running the export commands in your terminal before launching Claude Code.

Chapter 05, Verifying It Works

With Ollama running, your model downloaded, and your environment variables set, you're ready to launch Claude Code. Here's how to confirm everything is connected correctly.

Launch Claude Code. Navigate to a project folder in your terminal and run:

claude

Claude Code will start. If the environment variables are set correctly, it will not ask you to log in with an Anthropic account. It will launch directly into the chat interface, using your local Ollama model.

Check Which Model Is Running. Once inside Claude Code, ask it directly:

> What model are you running?

It should respond with the name of the Ollama model you pulled.

Quick Smoke Test. Try a simple coding task to confirm the full chain is working:

> Write a Python function to reverse a string and explain it

If you get a clear, correct response, everything is working.

Troubleshooting:

Claude Code asks me to log in, Your environment variables aren't being picked up. Run echo $ANTHROPIC_BASE_URL, if it's blank, you need to reload your shell profile or set the variables again in the current terminal session.

Slow responses, Expected, especially on CPU. The 30B model on a CPU without GPU acceleration can be slow. If speed matters, try the 7B model or check that Ollama is using your GPU with ollama ps.

Model not found error, Run ollama list to see exactly what's available. Use the exact model name that appears there when starting Claude Code.

Tool use not working, This is a known issue with some model and Ollama combinations. Go to /permissions inside Claude Code and check that Bash and file access are set to Allow.

Chapter 06, What to Expect

Local models are not the same as Claude Sonnet or Opus. They're genuinely capable for most coding tasks, but there are trade-offs worth knowing about before you rely on this as your primary setup.

What Works Well:

  • Reading and explaining existing code, local models handle this reliably
  • Boilerplate and scaffolding, form handlers, utility functions, component templates
  • Simple bug fixes and refactors on code already in front of it
  • Smaller tasks where the context fits cleanly in one request
  • Complete privacy, your code never leaves your machine

Where It Falls Short:

  • Complex multi-file reasoning, larger models handle this better
  • First-pass accuracy on harder problems, may need more back-and-forth than Sonnet
  • Speed on CPU, slower than the API, especially for longer outputs
  • Context limits, Ollama defaults can be low; set a higher context when starting: OLLAMA_NUM_CTX=32768 ollama serve

The Best Use Case. This setup is most useful in two scenarios. First: you're hitting API rate limits or costs and want to keep working, switch to local for the lighter tasks and save API credits for the harder ones. Second: you're working with code that can't leave your machine, client data, proprietary systems, anything where privacy is non-negotiable.

Switching Between Local and API. Create two shell aliases, one that sets the Ollama variables and one that clears them, and you can switch in seconds:

# Add to ~/.zshrc alias claude-local='export ANTHROPIC_BASE_URL=http://localhost:11434 && export ANTHROPIC_AUTH_TOKEN=ollama' alias claude-api='unset ANTHROPIC_BASE_URL && unset ANTHROPIC_AUTH_TOKEN'

Quick Reference:

# Step 1, Download Ollama # ollama.com (or: curl -fsSL https://ollama.com/install.sh | sh) # Step 2, Pull a model ollama pull qwen3-coder:30b # Powerful machine (16GB+ VRAM) ollama pull qwen2.5-coder:7b # Laptop / less powerful machine # Step 3, Set env variables (add to ~/.zshrc or ~/.bashrc) export ANTHROPIC_BASE_URL="http://localhost:11434" export ANTHROPIC_AUTH_TOKEN="ollama" export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 # Launch claude
