Claude Routines Setup Guide

Max Johnson @maxjohnscn

What Routines Are

Most automation tools, N8N, Make, Zapier, run fixed sequences. You define the steps, they execute them in order, every single time. They're pipelines, not thinkers.

Routines are different. A Routine is a saved Claude Code configuration: a prompt, one or more repositories, and a set of connectors. When it runs, Claude reads the situation, reasons about what it finds, and decides what to do. The same Routine can take completely different actions depending on what it encounters.

The other key difference: Routines run on Anthropic's servers. Your laptop doesn't need to be open. Your terminal doesn't need to be running. No cron job on your machine. No infrastructure to maintain. You configure it once and it keeps working in the background indefinitely.

What a Routine Contains

Every Routine has four configurable parts:

  • Prompt, Natural language instructions. What Claude should do, how to behave, what to output.
  • Repositories, One or more GitHub repos Claude can read and write to during each run.
  • Environment, Network access controls, environment variables (API keys, secrets), and a setup script that runs before each session.
  • Connectors, Pre-built integrations with services like Slack, Linear, Gmail, and Google Calendar.

Where to Find It

Routines are a Claude Code feature. You can create and manage them from three places, they all write to the same cloud account:

  • Web, go to claude.ai/code/routines
  • Desktop app, click New task, then New remote task
  • CLI, run /schedule inside any Claude Code session

Note: Routines are currently in research preview. Behaviour, limits, and the API surface may change.

Chapter 02, Setting Up a Routine

The entire configuration is one form. Prompt, repos, connectors, trigger. That's it. No YAML. No workflow builder. No node diagrams. You describe what you want done in plain language and Claude handles the rest.

1 Write Your Prompt

The prompt is the instruction Claude follows every time the Routine runs. Write it like you'd brief a smart assistant: what to look at, what to decide, what to produce.

TIP: Be specific about the output. If you want a Slack message, say so. If you want a draft PR, say so. Vague prompts produce vague results.

Example prompt for a nightly PR review:

Review all pull requests opened today in this repository.
For each PR: check for security issues, performance regressions,
and adherence to our coding standards (see CLAUDE.md).
Post a summary comment on each PR and send a digest to #dev-reviews
in Slack with any PRs that need urgent attention.

2 Connect Your Repositories

Add the GitHub repositories the Routine needs access to. Claude will be able to clone these repos, read the codebase, and push changes during each run.

TIP: By default, Routines can only push to branches prefixed with claude/. This protects main and other long-lived branches from accidental writes.

3 Add Connectors

Connectors give Claude tools to read from and write to external services during each run. Add the ones your Routine needs:

  • Slack, post messages, send digests, notify channels
  • Linear, create issues, update tickets, assign owners
  • Gmail, read emails, draft replies, send summaries
  • Google Calendar, check schedules, create events
  • GitHub, read issues, create PRs, post comments

Once your prompt, repos, and connectors are set, the last step is picking a trigger.

Chapter 03, Schedule Triggers

A Schedule trigger fires your Routine at a recurring time. Hourly, daily, weekdays, weekly, or a custom cron expression if you need something specific. You set the time in your local zone and Anthropic converts it automatically.

Setting a Schedule

In the Routine creation form, select Schedule as the trigger type. Choose one of the presets or enter a custom cron expression:

  • Hourly, fires every hour
  • Daily, fires once per day at a time you choose
  • Weekdays, fires Monday to Friday at a time you choose
  • Weekly, fires once per week on a day and time you choose
  • Custom cron, enter any valid cron expression

IMPORTANT: Cron expressions that run more frequently than once per hour are rejected. The minimum interval is 60 minutes.

What It's Good For

Schedule triggers are best for maintenance tasks that should happen regularly regardless of what's going on in the codebase:

  • Nightly backlog triage, reads new issues, applies labels, assigns owners, posts a summary to Slack
  • Weekly docs drift detection, scans merged PRs, flags documentation that references changed APIs
  • Daily standup prep, pulls open PRs, summarises overnight activity, posts to the team channel
  • Dependency audit, checks for outdated packages and opens a draft PR with updates

TIP: You can combine a Schedule trigger with other trigger types on the same Routine.

Chapter 04, GitHub Triggers

A GitHub trigger fires your Routine automatically when something happens in your repository. No manual prompting. No cron. Claude reacts to the event in real time.

Available GitHub Events

  • Pull request opened
  • Pull request merged
  • Release published
  • And more, check the trigger configuration form for the full list

Filtering Events

You can narrow exactly which events fire the Routine using filters:

  • PR author, only fire for PRs from specific team members or bots
  • Branch name, only fire for PRs targeting specific branches
  • Labels, only fire when a PR has a specific label applied
  • Draft status, ignore draft PRs, or only process them

Setting Up a GitHub Trigger

GitHub event-triggered Routines must be created from the web UI at claude.ai/code/routines. In the creation form, select GitHub event as the trigger type, choose your event, and select the target repository.

NOTE: GitHub triggers are not available from the CLI or Desktop app creation flow, use the web interface.

What It's Good For

  • Automated code review, fires on PR opened, applies your review checklist, posts inline comments
  • Library porting, fires on PR merged to one SDK, ports the change to a parallel SDK in another language
  • Deploy verification, fires after a release, runs smoke checks, posts go/no-go to the release channel
  • Issue labelling, fires on issue created, reads the content, applies relevant labels and assigns an owner

Chapter 05, API Triggers

Every Routine gets its own API endpoint. Send a POST request to that endpoint and the Routine fires immediately. No schedule to wait for. No GitHub event required. Fire it from anywhere.

How It Works

When you add an API trigger to a Routine, you get:

  • A unique endpoint URL at api.anthropic.com
  • A bearer token scoped to that Routine only, it cannot access any other account data

IMPORTANT: The bearer token is shown once in the modal and cannot be retrieved later. Copy it immediately and store it securely as an environment variable.

Making the Request

A POST request with your bearer token fires the Routine. You can pass optional context in the request body:

curl -X POST https://api.anthropic.com/v1/claude_code/routines/$ROUTINE_ID/fire \
-H "Authorization: Bearer $ROUTINE_TOKEN" \
-H "anthropic-beta: experimental-cc-routine-2026-04-01" \
-H "Content-Type: application/json" \
-d '{"text": "Alert ID 4521, stack trace: TypeError at line 83..."}'

The optional text field (up to 65,536 characters) passes freeform context to the Routine alongside the saved prompt.

What It's Good For

  • Alert triage, your monitoring tool calls the endpoint when an error threshold is crossed, passing the alert body as the text field
  • Deploy verification, your CD pipeline calls the endpoint after each production deploy
  • On-demand reports, internal tools can fire a Routine to generate a summary, analysis, or document without anyone opening Claude manually

Chapter 06, Real-World Examples

Nightly Backlog Triage. Trigger: Schedule (Weekdays, 8am). Connectors: GitHub, Slack, Linear. Reads issues opened since the last run. Applies labels, assigns owners based on the area of the codebase referenced, and posts a summary to Slack so the team starts the day with a groomed queue.

Automated PR Review. Trigger: GitHub (PR opened). Connectors: GitHub. Fires whenever a new PR is opened. Applies your review checklist, leaves inline comments for security, performance, and style issues, and adds a summary comment so human reviewers can focus on design decisions instead of mechanical checks.

Deploy Verification. Trigger: API. Connectors: GitHub, Slack. Your CD pipeline calls the endpoint after each production deploy, passing the deploy ID and environment as the text field. Claude runs smoke checks against the new build, scans error logs for regressions, and posts go/no-go to the release channel before the deploy window closes.

Weekly Documentation Drift. Trigger: Schedule (Weekly, Monday 9am). Connectors: GitHub. Scans all merged PRs from the past week. Flags documentation that references changed APIs and opens update PRs against the docs repository for a human editor to review and merge.

Chapter 07, Plan Limits and Gotchas

Routines are in research preview. A few things to know before you rely on them in a production workflow.

Daily Run Limits

Each plan tier has a cap on how many Routine runs can fire per day:

  • Pro, 5 runs per day
  • Max, 15 runs per day
  • Team or Enterprise, 25 runs per day

Usage beyond those caps can be billed as metered overage if extra usage is enabled on your account.

Branch Protection

By default, Routines can only push to branches prefixed with claude/. This prevents accidental writes to main, develop, release/*, or any long-lived branch. To allow pushes to any branch for a specific repository, enable Allow unrestricted branch pushes in the Routine's edit form.

Schedule Frequency

The minimum schedule interval is one hour. Cron expressions that run more frequently are rejected automatically.

API Token Security

Each API trigger token is shown once and cannot be retrieved later. Store it immediately as an environment variable. Tokens are scoped to a single Routine.

Research Preview Caveats

Behaviour, limits, and the API surface may change during the preview. Anthropic plans to expand webhook support beyond GitHub and graduate Routines to general availability, but no timeline has been confirmed.

TIP: You can manage Routines at claude.ai/code/routines. Each Routine's detail page shows past runs, click any run to open it as a full Claude Code session.
