Tip 01: Use the Most Capable Model to Plan, Cheaper Models to Execute

The most capable Claude models are specifically trained for delegation and orchestration. Let them do the planning and route the actual implementation to Sonnet or other models. Using the most powerful model at the orchestrator seat writing prompts for Sonnet workers is significantly cheaper than having it do everything itself.

The Prompt

Use the most capable model to plan this task but use Sonnet sub-agents
for the implementation: [insert task]

Tip 02: Match Effort Level to Task Complexity

In Claude Code, you can control how much reasoning Claude applies. Thinking tokens bill at output rates, running everything at maximum effort is one of the fastest ways to drain your limit.

LevelBest For
lowSimple Q&A, formatting, short rewrites
mediumSummarisation, standard content, research
highMost everyday work, the correct default
xhighComplex code review, multi-step reasoning
maxGenuinely hard unsolved problems only
TipAdd the effort level directly in your prompt: 'Use low effort for this, summarise the following in 5 bullets.'

Tip 03: Give Goals and Success Criteria, Not Step-by-Step Instructions

Micro-managing Claude with detailed step-by-step instructions forces more back-and-forth, which means more context reloads. Give it the outcome you want and what good looks like.

Template

Goal: [one sentence on what done looks like].
Success criteria: [what to check before calling it complete].
Check in after each major step.

For Long Tasks, Add This

Before marking this complete, verify your output against the success
criteria using fresh eyes, not your own working memory.

Tip 04: Stop Testing Powerful Models on Simple Tasks

The most capable models show their strengths on hard, long-horizon problems. Testing them on simple tasks is where a lot of unnecessary usage quietly goes. Do a routing check before every session.

Good Tasks for Most Capable Models

  • Large codebase refactors
  • Multi-stage analysis
  • Complex agent orchestration
  • Tasks that previously failed with other models

Use Sonnet Instead

  • Content creation
  • Standard coding
  • Research summaries
  • Anything you'd normally finish in under 10 messages
Routing CheckBefore opening the most powerful model, ask: could Sonnet handle this? If yes, use Sonnet.

Tip 05: Batch Context Up Front, Do Not Drip Feed It

More capable Claude models have a slow time-to-first-token because they reason heavily before answering. Every new message restarts that cycle. Turn-by-turn prompting is expensive. Send everything it needs upfront in one message and ask for the full deliverable.

Batching Template

Context: [background, relevant files, constraints].
Task: [the full deliverable].
Output format: [length, structure, what to skip].
Success looks like: [what done means].

Add This to Cap Verbosity

Be concise. Stop when the task is complete, do not summarise what
you did or explain your reasoning unless I ask.

Tip 06: Cap Output Length Explicitly

Claude can generate up to 128,000 output tokens in a single response. One uncapped agentic run can burn significant usage just on output. Most tasks don't need anywhere near that. Add a cap to every prompt.

Word Count Caps

  • "Keep this under 300 words."
  • "Answer in 3 sentences or fewer."

Format Constraints

  • "Bullet points only. Max 6 bullets."
  • "Output only, no preamble."

Add to User Preferences

Default to concise responses. I will ask for detail when I need it.
Never summarise what you just did.

Tip 07: Remove Old Show-Your-Reasoning Instructions

If you have prompts or system instructions that say "think step by step," "show your work," or "explain your reasoning", remove them for Claude's most capable models. The models reason internally by default. Externalising that reasoning adds output tokens for content you will mostly scroll past.

Remove These

  • "Think step by step"
  • "Show your work"
  • "Explain your reasoning"
  • "Walk me through it"

Replace With

If you are uncertain about any step, flag it briefly.
Otherwise give me the output directly.

Tip 08: Watch Your Window With Agentic Tasks

Agentic Claude Code sessions can silently branch into 4-6 concurrent model calls as sub-agents spin up. Each runs its own context. The Claude Code status line shows your remaining 5-hour and weekly budget, check it before walking away from a long session.

Use a maximum of 3 sub-agents. Prioritise sequential work over
parallel where both would work. Check in with me before spawning
more than 2 agents.
4-6x

Concurrent model calls in uncontrolled agentic sessions

2x

Usage counted per message for most capable models on subscription plans

128k

Max output tokens per response, cap it explicitly

Tip 09: Use Memory Files for Long-Running Projects

For anything running across multiple sessions, give Claude a place to log decisions, even a simple markdown file. This avoids re-paying for context that is already established.

Memory File Prompt

Maintain a DECISIONS.md file. After each major decision or completed
step, log what was decided, why, and any constraints to carry forward.
At the start of each new session, read this file before starting,
do not ask me to re-explain what is already there.

Tip 10: Know What's Changing on Usage Pricing

Anthropic has been updating how usage is counted for its most capable models. If you are building the most powerful Claude models into regular workflows, understand the current pricing model and how it applies to your plan, Pro, Max, Team, and Enterprise all have different limits and overage rules.

The core principle stays the same regardless of when you're reading this: use the most capable models for what they were built for, hard, long-horizon problems that genuinely need them. Everything else goes to Sonnet.

The SummaryThat one routing habit does more than every other tip on this list combined.

The Habit That Does Most of the Work

Route hard problems to the most capable model. Route everything else to Sonnet. Apply effort levels. Cap your output. These aren't complicated changes, they're habits. Build them once and your usage window stops being a constraint.

  • Plan with the most capable model, execute with Sonnet or lighter sub-agents.
  • Match effort level to task complexity, default to high, not xhigh.
  • Send full context upfront, never drip-feed a long task turn by turn.
  • Cap output length explicitly on every prompt you send.
  • Maintain a DECISIONS.md for anything spanning multiple sessions.
