How to read this

You do not need all thirteen on day one. Namecheap through Vercel gets a real product live. Resend and Stripe get added when you have users and a price. PostHog, Sentry, Upstash and Pinecone get added only once something specific calls for them, slow queries, silent bugs, an AI feature. Add tools when the problem shows up, not before.

Tools 01-03 of 13

01
Namecheap$12/yr

Buying the domain.

  • Registering your main domain and any variants you want to redirect (e.g. buying both .com and .co so someone else can't grab it)
  • Setting up domain privacy so your name and address aren't public in WHOIS lookups (usually included free, check at checkout)
  • Buying a second domain for a landing page or side project without committing to a full hosting setup
02
CloudflareFree

DNS, but it does more than just point your domain.

  • Free SSL certificate so your site runs on https without you doing anything
  • Proxying your traffic through Cloudflare so your actual server IP is hidden, which cuts down bot traffic and basic DDoS attempts
  • Page rules to redirect old URLs, force www or non-www, or cache static assets at the edge so your site loads faster globally
03
GitHubFree

Version control, and your safety net.

  • Every commit is a point you can roll back to, especially useful if Claude makes a change that breaks something
  • Branching so you can build a new feature without touching your live code, then merge once it works
  • GitHub Actions for basic automation, like running tests automatically every time you push
  • Private repos by default if you're not ready for anyone to see the code

Tools 04-06 of 13

04
Claude$20/mo

Writing and shipping the code, the only paid tool until you've got users.

  • Scaffolding a new feature from a plain English description instead of writing boilerplate yourself
  • Debugging: paste an error and the surrounding code, get the actual fix instead of guessing
  • Refactoring old code once it works but is messy, without breaking what already works
  • Writing tests you'd otherwise skip because you're moving fast solo
05
SupabaseFree

Your backend, database included.

  • Postgres database for anything structured: users, orders, posts, whatever your app stores
  • Storage buckets for file uploads, profile pictures, documents, generated files
  • Row-level security so users can only see and edit their own data, set once and it's enforced everywhere
  • Edge functions for backend logic you don't want running in the browser, like calling a paid API with a secret key
06
ClerkFree

Auth, so you're not building login from scratch.

  • Email and password, or social login (Google, GitHub) with almost no setup
  • Session handling so users stay logged in without you managing tokens manually
  • Webhooks that fire when someone signs up, so you can create their record in Supabase automatically
  • Multi factor auth if you're handling anything sensitive, turned on with a toggle not custom code

Tools 07-09 of 13

07
VercelFree

Deploying, connected straight to GitHub.

  • Push to GitHub, it deploys automatically, no manual upload
  • Preview deployments: every pull request gets its own live URL so you can test a feature before merging it
  • Environment variables kept out of your code, so API keys never end up in a public repo by accident
  • Serverless functions if you need small bits of backend logic without spinning up a whole server
08
ResendFree

Transactional email, the emails your app has to send.

  • Welcome email when someone signs up
  • Password reset links
  • Receipts after a Stripe payment goes through
  • Using React Email to design these so they don't look like plain text dumped into an inbox
09
Stripe2.9% per txn

Payments, no monthly cost so set it up early.

  • Stripe Checkout for a hosted payment page, fastest way to start taking money
  • Subscriptions if you're charging monthly or yearly instead of once
  • Webhooks so your app knows the moment a payment succeeds or fails, and can update the user's account automatically
  • Usage based billing if you're charging per action instead of a flat fee

Tools 10-13 of 13

10
PostHogFree

Analytics, so you're not guessing what users do.

  • Tracking key events: signup, first action taken, upgrade, so you know where people drop off
  • Funnels to see exactly what percentage of visitors make it from landing page to paying customer
  • Session recordings to literally watch a user struggle with something in your app
  • Feature flags to roll out a new feature to a small percentage of users before everyone gets it
11
SentryFree

Error tracking, so bugs don't rely on users reporting them.

  • Full stack traces the second something breaks in production
  • Alerts sent to you the moment an error happens, not when someone emails to complain
  • Release tracking so you know exactly which deploy introduced a bug
12
UpstashFree

Redis, add this once something is slow or needs limits.

  • Caching data you fetch often but doesn't change much, so you're not hitting your database every time
  • Rate limiting an API endpoint so one user can't spam it and rack up your costs
  • Storing temporary session data outside your main database
13
PineconeFree

Vector database, only if you're building AI search or recommendations.

  • Semantic search, letting users search by meaning instead of exact keyword match
  • Powering a RAG setup, where your AI feature pulls relevant context from your own data before answering
  • Recommendation logic based on similarity, this is like that

Thirteen Tools. One At A Time.

You don't need the full stack to start. Most of it is free, the paid parts only bite once you actually have something worth paying for, and every tool here earns its place at a specific point, not before.

  • Ship first: Namecheap, Cloudflare, GitHub, Claude, Supabase, Clerk, Vercel. That's a live, working product.
  • Add when you charge: Resend for the emails a paying product has to send. Stripe when money starts moving.
  • Add when you have users: PostHog to see what they actually do. Sentry so bugs don't rely on someone emailing you.
  • Add when something specific hurts: Upstash for a slow query or a rate limit. Pinecone only if you're building AI search.
