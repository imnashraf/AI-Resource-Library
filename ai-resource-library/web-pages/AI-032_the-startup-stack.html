01, Claude

Claude is the brain behind everything in this stack. Most people use it to answer questions. That is the least interesting thing you can do with it.

How to actually use it:

  • Set up a project in Claude and give it context about what you are building. The more it knows upfront, the better everything it produces will be.
  • Use it as your strategist first. Before writing a single line of code, tell Claude your idea and ask it to stress test it. What is the biggest risk? Who is this actually for? What would make it fail?
  • Run your entire workflow through it. Copy, strategy, research, code review. If you are switching between five different tools to do these things, consolidate them into Claude.
  • Give it a memory by uploading documents, previous chats, or a brief at the start of every session. It has no memory between conversations by default so the more context you give it, the sharper it gets.
  • Use Claude for the thinking. Use Claude Code for the building. The two together are where the real speed comes from.

The people getting the most out of Claude are not asking it one question at a time. They are running entire workflows through it.

02, Cookiy

Cookiy is a free skill you add directly into Claude. It lets you find real people and interview them on any idea you have. Not surveys. Not guesswork. Actual conversations with the exact people you want to speak to.

Why this matters. Most founders skip user research because it is too slow and too expensive. Agencies charge thousands. It takes weeks. By the time you get the results the moment has passed. Cookiy removes all of that.

How to use it:

  • Add the Cookiy skill to Claude. It is free to install and takes about two minutes to set up.
  • Type /cookiy and describe your idea. Then tell it who you want to speak to. Age, location, profession, whatever is relevant. Be specific.
  • Cookiy goes and finds those exact people and runs the interviews for you. Real people, on camera. You get back the recordings, the transcripts and a full analysis, all inside Claude.
  • Use it before you build anything. The single most common mistake founders make is building something nobody wants. One round of interviews before you start will save you months.
  • Use it while you are building too. Run a quick round every time you are about to make a big product decision. It takes a day and costs less than a meal out.

A full 15 minute interview with a recruited respondent costs $9.90. That includes finding the person for you. There is nothing else out there that comes close to that.

03, Figma

This is where your product gets designed. It is the industry standard and pretty much everyone you will ever work with already knows how to use it.

How to use it:

  • Start with a simple wireframe before you touch Claude Code. Even a rough layout will save you hours of back and forth when you start building.
  • Use Figma's component system. Build your buttons, cards and inputs as reusable components from the start. When something changes you update it once and it updates everywhere.
  • Share it with collaborators using the observer link. Anyone you bring in, whether a designer, developer or co-founder, can see exactly what you are building without needing edit access.
  • Export assets directly into your project. Icons, images, anything you design in Figma can be dropped straight into your build.

You do not need to be a designer to use Figma. You just need to be clear about what you want to build. Start simple and add detail as you go.

04, Claude Code

This is how you build your product without needing a developer. It runs inside Claude, which means everything you are already doing connects straight into it.

How to use it:

  • Give it your Figma designs as context. The more visual reference it has, the closer the output will be to what you actually want.
  • Be specific about what you are asking it to build. Vague prompts produce vague code. Tell it exactly what the component should do, what it should look like and how it should behave.
  • Review every change before it moves on. Claude Code works best when you are in the loop, not just letting it run. Check the output, give feedback and iterate.
  • Use it for debugging too. Paste in an error and tell it what you were trying to do. It will usually find the problem faster than searching Stack Overflow.
  • Combine it with Claude for the thinking layer. Use Claude to plan what you are building, then hand it off to Claude Code to actually build it.

It is probably the fastest way to go from idea to working product right now. Especially when you combine it with everything else in this stack.

05, N8N

Once everything is running you need it all connected. N8N handles your automations so the repetitive stuff just runs in the background on its own.

How to use it:

  • Start with one automation, not ten. Pick the most repetitive thing you do every week and build a workflow for that first. Get comfortable with how N8N works before you scale it.
  • Connect it to your other tools. N8N integrates with most things you are already using. Notion, Slack, Gmail, Airtable, Google Sheets. If data needs to move between them, N8N can handle it.
  • Use Claude inside your N8N workflows. You can pipe data through Claude to summarise, analyse or generate content as part of an automated flow. This is where things get genuinely powerful.
  • Build your Cookiy research results into a workflow. Once interviews come back, use N8N to automatically format the insights and send them to wherever your team works.
  • Self-host it if you can. N8N is open source and free to run on your own server. It gives you full control and removes any per-task pricing.

The goal with N8N is to remove yourself from the things that do not need you. Every hour you spend on repetitive tasks is an hour you are not spending on building.
