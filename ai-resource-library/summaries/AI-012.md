## 1. What This Resource Teaches  
This guide explains how to replace the default Anthropic cloud endpoint used by Claude Code with a locally hosted Ollama server, thereby eliminating API fees and preserving code privacy. It walks the reader through installing Ollama, selecting an appropriate open‑source coding model, configuring three environment variables, and confirming that Claude Code is now routing its requests to the local model.  

The underlying architecture hinges on Ollama’s ability to expose an HTTP API that mirrors the Anthropic Messages format. By pointing Claude Code at `http://localhost:11434` and supplying a dummy auth token, the tool believes it is communicating with the official service while the heavy lifting is performed on the user’s own hardware. The tutorial also outlines performance expectations, hardware requirements, and troubleshooting tactics for common pitfalls such as missing environment variables or GPU mis‑configuration.

## 2. Why It Matters  
Redirecting Claude Code to a self‑hosted model removes recurring usage costs and eliminates rate‑limiting constraints that can stall development pipelines. For teams handling proprietary or regulated codebases, keeping all data on‑premises satisfies compliance and confidentiality mandates. Moreover, the approach democratizes access to advanced coding assistants: anyone with a modest GPU or sufficient RAM can run a capable model without relying on external services. This shift aligns with broader industry trends toward edge AI and cost‑effective, privacy‑first tooling.

## 4. Key Concepts & Principles  

- **Local API Proxying**: Ollama implements a thin wrapper that accepts Anthropic‑style payloads, enabling existing Claude Code clients to operate unchanged while the request is processed locally.  
- **Mixture‑of‑Experts (MoE) Scaling**: The recommended 30‑billion‑parameter model activates only a subset of its parameters per token, delivering near‑30B quality with 3‑B‑like latency when sufficient VRAM is present.  
- **Environment‑Variable Redirection**: Three variables (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`) control the endpoint, authentication stub, and telemetry suppression, respectively.  
- **Hardware‑Aware Model Selection**: Choosing between a 30B MoE model and a 7B baseline depends on GPU VRAM (≥16 GB) or system RAM (≥32 GB) availability, balancing speed, memory footprint, and model capability.

## 5. Tools & Technologies Mentioned

- **Ollama** – A cross‑platform runtime that downloads, quantizes, and serves open‑source LLMs via a RESTful endpoint on port 11434; it abstracts GPU/CPU execution details.  

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Zero‑Cost Local Coding Assistant  
1. **Install Ollama** (macOS/Windows installer or `curl -fsSL https://ollama.com/install.sh | sh` on Linux).  
2. **Pull the desired model**:  
   - For high‑end hardware: `ollama pull qwen3-coder:30b`  
   - For laptops or limited RAM: `ollama pull qwen2.5-coder:7b`  
3. **Add environment variables** to `~/.bashrc` or `~/.zshrc`:  
   ```bash
   export ANTHROPIC_BASE_URL="http://localhost:11434"
   export ANTHROPIC_AUTH_TOKEN="ollama"
   export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
   source ~/.zshrc   # or source ~/.bashrc
   ```  
4. **Start Claude Code** with `claude`. The tool should launch directly into the chat UI without prompting for an Anthropic key.  
5. **Validate** by asking “What model are you running?” – the response should echo the model name you pulled.  

### Use Case 2 – Rapid Switching Between Local and Cloud Back‑ends  
1. Define two shell aliases in your profile:  
   ```bash
   alias claude-local='export ANTHROPIC_BASE_URL=http://localhost:11434 && export ANTHROPIC_AUTH_TOKEN=ollama'
   alias claude-api='unset ANTHROPIC_BASE_URL && unset ANTHROPIC_AUTH_TOKEN'
   ```  
2. When you need to conserve API quota, run `claude-local` before invoking `claude`.  
3. For tasks that demand the higher quality of Claude Sonnet/Opus, execute `claude-api` to revert to the official Anthropic endpoint.  
4. This pattern enables on‑the‑fly cost management without reinstalling or reconfiguring software.
