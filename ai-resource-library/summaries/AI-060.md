## 1. What This Resource Teaches  
The guide introduces a structured prompt that lets you audit an AI skill or MCP (Machine‑Learning‑Powered Component) before you install it. It teaches you how to treat the code as untrusted, read every file in isolation, and systematically evaluate six critical risk vectors: credential leakage, hidden network traffic, arbitrary code execution, filesystem manipulation, obfuscation, and prompt‑injection tricks. By following the prompt, you learn to ask an AI chatbot to parse the source, flag suspicious patterns, and produce a concise verdict. The resource also shows how to interpret the AI’s output, ensuring you can make an informed decision about whether the component is safe to run.

## 2. Why It Matters  
In modern AI pipelines, skills and MCPs are often distributed as open‑source packages that can read environment variables, execute shell commands, or reach out to external services. A single malicious or poorly written component can expose API keys, exfiltrate data, or compromise the host system. This guide equips developers and security teams with a lightweight, repeatable audit that can be performed before any code is executed, reducing the attack surface and fostering a culture of proactive security. It also demonstrates how AI chatbots can serve as automated auditors, turning a manual code review into a quick, repeatable process.

## 4. Key Concepts & Principles  
- **Credential Access** – Detecting any read of environment variables, `.env` files, or credential stores that might expose secrets.  
- **Network Activity** – Identifying outbound HTTP/HTTPS calls, hard‑coded URLs, or dynamic endpoints that could leak data.  
- **Code Execution** – Spotting subprocess calls, `eval`, or lifecycle hooks that run arbitrary code during installation.  
- **File System Access** – Checking for reads/writes outside the component’s own directory, including system folders or startup scripts.  
- **Obfuscation** – Decoding base64, hex, or minified payloads to reveal hidden logic.  
- **Prompt Injection** – Looking for invisible or hidden instructions that could manipulate the AI’s behavior during execution.

## 6. Practical Use Cases & Workflows  
- **Use Case / Workflow 1 – Pre‑Installation Audit**  
  1. Clone the skill: `git clone https://github.com/user/skill.git`  
  2. Enter the directory: `cd skill`  
  3. Copy the entire repository path or zip file.  
  4. Paste the safety‑check prompt into your chosen chatbot, replacing `[PASTE GITHUB LINK OR UPLOAD THE FILES/ZIP]` with the actual link or file.  
  5. Review the AI’s verdict and findings.  
  6. If the verdict is **SAFE**, proceed with installation; otherwise, investigate or refuse.

- **Use Case / Workflow 2 – CI/CD Integration**  
  1. Add a script step in your pipeline that runs the safety‑check prompt against any new pull request.  
  2. Capture the AI’s output in a log file.  
  3. Fail the build if the verdict is **NOT SAFE** or if any of the six checks fail.  
  4. Notify the developer with a summary of the problematic lines and files.
