## 1. What This Resource Teaches  
This guide explains how Claude’s token accounting works and why long, untrimmed conversations quickly become expensive. It introduces a set of practical habits—ranging from command‑line shortcuts to project‑level configuration—that let users keep the model’s context lightweight while preserving the essential information needed for continuity.  

Each tip is paired with concrete steps (e.g., invoking `/compact`, editing prompts in‑place, batching questions) and with higher‑level settings such as Project memory, system prompts, and model selection. By the end of the material, a practitioner can design a repeatable workflow that minimizes both input and output token consumption without sacrificing answer quality.  

## 2. Why It Matters  
Token usage directly translates to cost and quota exhaustion on Claude. Unintended re‑reading of redundant history or duplicated document uploads can inflate consumption by orders of magnitude, especially in iterative brainstorming sessions. Implementing the recommended patterns yields measurable savings—often cutting usage by 70‑90 % for a typical back‑and‑forth dialogue—thereby extending the usable lifespan of a subscription and freeing budget for higher‑value tasks.  

Beyond economics, leaner context improves response latency and reduces the chance of the model drifting away from the core problem, because it only sees the most relevant information. This aligns with best practices for prompt engineering and scalable AI product design.

## 4. Key Concepts & Principles  

- **Context Compression (`/compact`)** – A built‑in command that replaces the full message history with a concise summary, preserving essential facts while discarding filler.  
- **In‑Place Prompt Editing** – Modifying the original user message rather than appending a correction, which prevents the model from retaining the erroneous response in its context.  
- **Conversation Reset Cadence** – Proactively starting a new chat after roughly 15‑20 exchanges, using a generated summary to transfer only the needed state.  
- **Project‑Level File Caching** – Uploading recurring documents once to a Claude Project so that subsequent chats can reference them without re‑tokenizing the content.  

## 5. Tools & Technologies Mentioned

- **Claude Projects** – A workspace feature that stores files, system prompts, and user preferences, making them globally available to every chat launched within the project.  

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Maintaining a Long‑Running Research Thread  
1. **Start a Project** and upload the research PDFs, brand guidelines, and any reference PDFs.  
2. **Set User Preferences** once (role, tone, brevity) in the Project’s Memory tab.  
3. **Ask the first question**; after 12‑15 exchanges, type `/compact` to collapse the history.  
4. **If a response is off‑target**, click the edit icon on the original prompt, adjust the wording, and resend.  
5. **When the thread reaches ~20 messages**, request a summary (`Summarise everything we have covered…`), copy the output, open a new chat, paste the summary as the opening prompt, and continue.  

### Use Case 2 – Batch‑Processing Customer Support Queries  
1. **Collect all pending tickets** and list them as a numbered set in a single message.  
2. **Add a length constraint** (`Answer each in ≤ 2 sentences`).  
3. **Send the batch**; Claude processes the entire list in one context load, returning concise replies.  
4. **Reference the uploaded FAQ document** from the Project instead of pasting its full text, saving token duplication.
