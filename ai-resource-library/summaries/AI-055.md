## 1. What This Resource Teaches  
The guide shows how to orchestrate three distinct LLM‑powered command‑line tools—Claude Code, Codex CLI, and Gemini CLI—through a lightweight MCP server called PAL. By doing so, you can keep a single terminal session while delegating tasks to the model that best matches the problem type: Claude Code for high‑level design and file manipulation, Codex CLI for execution‑aware code review, and Gemini CLI for large‑context analysis.  

It walks you through the prerequisites (Node.js, Git, Python 3.10+, uv), the installation of each CLI, and the configuration of the PAL server so that Claude Code can invoke the other tools as “tools” in its own prompt. The result is a seamless, multi‑model workflow that eliminates manual file copying and reduces context‑window limitations.  

Finally, the guide supplies ready‑to‑use prompt patterns (dual‑review, large‑codebase analysis, architecture disagreement, automated review hook, document analysis) that illustrate how to explicitly route work to the appropriate model, turning the system into a disciplined, repeatable AI development pipeline.

## 2. Why It Matters  
Modern codebases often exceed the token limits of a single LLM, and each model has its own blind spots shaped by its training data. Relying on one model can trap you in an echo chamber where the same mistakes are repeated. By combining Claude, Codex, and Gemini, you gain complementary perspectives: reasoning, execution awareness, and massive context capacity.  

The PAL MCP server removes the friction of juggling multiple terminals, letting you stay in Claude Code while the system automatically hands off tasks. This boosts developer productivity, reduces cognitive load, and makes it easier to enforce consistent quality checks (e.g., automated Codex reviews after every commit).  

Because the workflow uses existing subscription plans rather than API keys, it keeps costs predictable while still leveraging the strengths of each provider’s model.

## 4. Key Concepts & Principles  
- **Model Complementarity**: Each LLM excels in a different dimension—Claude in intent reasoning, Codex in execution logic, Gemini in large‑scale context. Leveraging all three mitigates blind spots.  
- **Echo Chamber Mitigation**: By routing the same question to multiple models, disagreements surface as signals that something may be wrong, breaking the self‑reinforcing loop of a single model’s confidence.  
- **Context Window Scaling**: Gemini’s ~1 M‑token window allows whole‑project analysis, while Claude and Codex handle focused, file‑level changes. Choosing the right model for the token budget is critical.  
- **Tool‑Based Prompt Engineering**: Explicitly calling `pal_ask_codex` or `pal_ask_gemini` in prompts gives deterministic routing, turning the AI into a programmable workflow engine.

## 5. Tools & Technologies Mentioned  
- **Claude Code**: A local CLI that runs Claude models, handles file edits, and serves as the session coordinator.  
- **Codex CLI**: OpenAI’s command‑line interface that can execute code and perform logic‑heavy reviews.  
- **Gemini CLI**: Google’s CLI for Gemini models, optimized for large‑context tasks.  
- **PAL MCP Server**: A lightweight Python server that exposes Codex and Gemini as callable tools for Claude Code.  
- **uv**: Fast Python package manager used to install PAL’s dependencies.  
- **Node.js (≥20)** and **Git**: Runtime prerequisites for installing the CLIs.  
- **Python 3.10+**: Required to run PAL and its sandboxed environment.

## 6. Practical Use Cases & Workflows  
### Use Case 1 – Dual‑Review Build Pipeline  
1. **Start a Claude Code session** and describe the feature you’re adding.  
2. Claude writes the necessary files.  
3. Prompt:  
   ```
   Use Codex to review the changes in auth.js for logic errors, off‑by‑one bugs, and edge cases. Return both your notes and Codex’s findings side by side.
   ```  
4. Claude automatically calls `pal_ask_codex`, receives the review, and presents a side‑by‑side comparison.  
5. Commit only after both reviews agree or after you resolve any disagreements.

### Use Case 2 – Large‑Codebase State‑Mutation Scan  
1. In Claude Code, run:  
   ```
   Use Gemini to read the entire src/ directory and list every file that mutates state outside a dedicated state‑management module. Return file paths and line numbers.
   ```  
2. Gemini processes the full repository (thanks to its 1 M‑token window) and returns a concise report.  
3. Use the report to refactor state mutations into a centralized store, improving maintainability.
