## 1. What This Resource Teaches  
This guide demonstrates how to harness the complementary strengths of two leading LLMs—Claude Opus and GPT‑5.5—within a single development session. It walks the reader through the prerequisites, installation of the Codex CLI, and the lightweight `skill-codex` plugin that bridges Claude Code with the Codex agent. By issuing a simple natural‑language trigger, the workflow automatically hands off a code diff from Claude to Codex for a fresh, diff‑focused audit. The resource explains how to interpret the dual‑model output, manage token costs, and maintain a human‑in‑the‑loop decision process. The emphasis is on practical, low‑overhead integration rather than theoretical benchmarking, showing developers how to get the best of both worlds without extra tooling complexity.

## 2. Why It Matters  
In real‑world codebases, a single model often falls short: one excels at generating code with full context, while another shines at spotting subtle logic errors in a narrow diff. By combining Claude’s holistic understanding with GPT‑5.5’s focused review, teams can:

- **Reduce defect rates**: Codex’s fresh perspective catches edge cases that Claude may overlook after long context exposure.  
- **Improve productivity**: Developers can iterate quickly with Claude and then receive a concise audit from GPT‑5.5, shortening the review cycle.  
- **Optimize costs**: The token budget is dominated by Claude’s generation; Codex’s review consumes only a fraction of that, keeping overall spend lower than running two full‑context calls.  
- **Future‑proof workflows**: As models evolve, the dual‑model pattern remains valid; swapping or adding new agents becomes a matter of updating the plugin rather than re‑architecting the pipeline.

## 4. Key Concepts & Principles  
- **Complementary Model Strengths**: Claude Opus excels at full‑context generation; GPT‑5.5 excels at token‑efficient, diff‑focused auditing.  
- **Dual‑Model Workflow**: A sequential handoff—Claude builds, Codex reviews—maximizes coverage while minimizing redundancy.  
- **Contextual vs Diff‑Based Review**: Full‑context models can miss fresh errors; diff‑only models bring a fresh eye to recent changes.  
- **Token Cost Optimization**: By limiting Codex to the diff, the overall token usage stays below the sum of two full‑context calls, keeping costs manageable.

## 5. Tools & Technologies Mentioned  
- **Claude Code**: IDE‑like interface for Claude, enabling natural‑language prompts and code editing.  
- **Codex CLI** (`@openai/codex`): Command‑line agent that runs GPT‑5.5 locally, capable of reading, editing, and executing shell commands.  
- **skill‑codex Plugin**: Open‑source connector that registers the Codex CLI with Claude Code, handling the handoff logic.  
- **npm**: Node package manager used to install Codex CLI globally.  
- **Git**: Version control system required to fetch the plugin from the marketplace or GitHub.  

## 6. Practical Use Cases & Workflows  
### Use Case 1: Build‑and‑Audit a Rate Limiter  
1. **Generate**: In Claude Code, ask “Create a basic rate limiter for API routes.”  
2. **Review**: Trigger Codex with `Review this file with Codex before we ship.`  
3. **Inspect**: Examine Claude’s summary and Codex’s diff‑audit for bypass scenarios.  
4. **Iterate**: Adjust code based on Codex feedback, then re‑trigger if needed.  

### Use Case 2: Refactor Database Connection Pooling  
1. **Refactor**: Use Claude to rewrite the pooling logic across the repo.  
2. **Targeted Review**: Prompt `Codex, check the last three commits for edge cases we might have missed.`  
3. **Validate**: Look for race‑condition flags from Codex, reconcile with Claude’s notes.  
4. **Deploy**: Commit changes once both models agree or after manual resolution of disagreements.
