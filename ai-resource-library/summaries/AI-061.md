## 1. What This Resource Teaches

This resource shifts the paradigm from static "prompt engineering" to dynamic "context engineering." It argues that the primary value in modern LLM workflows lies not in crafting clever one-off instructions, but in establishing persistent, reusable context structures (Skills, Projects, and Memory). The guide provides a comprehensive library of 33 specialized prompts designed to be saved as reusable assets, ensuring that specific voice, formatting rules, and operational standards are inherited across sessions without repetitive manual input.

The core technical mechanic introduced is the "Pre-Flight Interview" and "Plausibility Audit." Rather than accepting the model's initial confident output, these workflows force the AI to interrogate the user for missing constraints before generating code or content, and to explicitly flag its own uncertainty levels after generation. This transforms the LLM from a passive generator into an active verification partner, reducing the risk of "hallucinated confidence" where syntactically correct but semantically wrong outputs are produced.

Architecturally, the guide organizes these prompts into eight functional domains: Writing, Coding, Data, Product, Sales, Research, Productivity, and Decision-Making. Each domain addresses specific failure modes, such as "AI-slop" in writing, deprecated API usage in coding, or survivorship bias in data analysis. The underlying philosophy is that high-value AI usage requires structured verification loops and explicit confidence calibration rather than blind trust in the model's fluency.

## 2. Why It Matters

In an era where LLMs can produce highly plausible but factually incorrect information (the "Plausibility Trap"), this resource provides a defensive framework for professional use. By institutionalizing self-verification and uncertainty flagging, users can mitigate the risk of shipping broken code, misleading data insights, or generic content. This is critical for enterprise and professional workflows where the cost of error is high.

The emphasis on "reusable skills" addresses the scalability problem of prompt engineering. If every task requires a unique, complex prompt, the cognitive load on the user remains high. By converting best practices into saved, parameterized templates, teams can democratize high-quality AI usage. This ensures that output quality is consistent regardless of which team member is interacting with the model, reducing dependency on individual "prompt-savvy" experts.

Furthermore, the guide highlights the strategic shift toward "AI Citability" and "De-Slop" passes. As AI-generated content floods the internet, the ability to produce distinct, human-sounding, and factually rigorous content becomes a competitive advantage. The tools provided here help users maintain brand integrity and credibility in a saturated digital landscape.

## 4. Key Concepts & Principles

- **Context Engineering over Prompt Engineering**: The principle that persistent context (via Skills, Projects, and Memory) is more valuable than ephemeral, one-off prompts. This involves teaching the model your specific voice, rules, and formats once, so they are automatically applied in future interactions.
- **The Plausibility Trap & Confidence Calibration**: The recognition that LLMs often present incorrect information with high confidence. The counter-strategy is to explicitly prompt the model to rate its own confidence (certain, probably right, unsure) and to flag uncertainty before finalizing outputs.
- **Pre-Flight Interview (Clarification Loop)**: A workflow pattern where the model is instructed to ask clarifying questions about ambiguous requirements *before* generating a solution. This prevents the model from guessing at edge cases or data shapes, which is a primary source of downstream errors.
- **De-Slop & AI Citability**: The practice of auditing content for specific markers of AI generation (e.g., em-dash overuse, vague attributions, "rule of three" lists) and rewriting to ensure specificity and human authenticity. Conversely, "AI Citability" refers to structuring content so that other AI systems can easily extract and cite it as a reliable source.

## 5. Tools & Technologies Mentioned

- **Claude (Sonnet 5, Opus 5, Haiku 4.5)**: The primary LLM platform. The guide differentiates use cases by model tier: Sonnet 5 for general high-quality tasks, Opus 5 for complex reasoning and high-stakes decisions, and Haiku 4.5 for high-volume, low-stakes batch processing.
- **Claude Skills / Projects**: Native features within the Claude interface that allow users to save reusable prompt templates, context documents, and system instructions. These are the primary mechanism for implementing the "Context Engineering" principle.
- **ChatGPT / Perplexity / AI Overviews**: Mentioned in the context of the "AI Citability Audit." These are external AI systems whose citation behavior is being optimized for, indicating a focus on SEO for AI (AEO) rather than traditional search engine optimization.

## 6. Practical Use Cases & Workflows

- **Workflow: Robust Code Generation**
    1.  **Initiate Pre-Flight Interview**: Paste a rough feature description into the "Pre-Flight Interview" prompt.
    2.  **Clarify Constraints**: Answer the model's questions one by one regarding edge cases, data shapes, and error handling until the model confirms it has sufficient context.
    3.  **Generate Code**: The model produces code based on the clarified spec.
    4.  **Run Plausibility Audit**: Paste the generated code into the "Plausibility Audit" prompt.
    5.  **Review Flags**: The model identifies deprecated methods, non-existent libraries, and semantic errors, rating its confidence for each flag.
    6.  **Self-Verification**: Use the "Self-Verification" prompt to have the model check its work against specific acceptance criteria before marking the task as "done."

- **Workflow: High-Quality Content Production**
    1.  **Establish Voice**: Use the "Turn Your Voice Into a Reusable Skill" prompt with 3-5 writing samples to generate a saved voice guide.
    2.  **Draft Content**: Generate a draft using the saved voice guide.
    3.  **De-Slop Pass**: Run the draft through the "De-Slop Pass" prompt to identify and rewrite specific AI-sounding phrases (e.g., vague attributions, filler openers).
    4.  **AI Citability Audit**: If the content is for public consumption, run the "AI Citability Audit" to ensure the opening is a self-contained, quotable answer block suitable for extraction by other AI systems.
    5.  **Final Review**: Manually review the flagged lines and the rewritten sections to ensure brand alignment.

## 7. Prerequisites

- **Access to Claude**: A subscription or API access to Claude, specifically with the ability to use "Projects" or "Skills" features for saving context.
- **Basic Prompt Engineering Knowledge**: Understanding of how to structure prompts with variables (e.g., `[PASTE DRAFT]`) and how to define output formats.
- **Domain Expertise**: The prompts are generic frameworks; the user must possess sufficient domain knowledge to evaluate the model's output, answer clarifying questions, and verify the "plausibility" of the results.
- **Familiarity with LLM Limitations**: An understanding of hallucinations, confidence calibration, and the difference between syntactic correctness and semantic accuracy.
