## 1. What This Resource Teaches  
This guide walks a developer through constructing a persistent, graph‑based representation of a code repository so that Claude‑powered coding assistants can retrieve context without repeatedly ingesting raw source files. The core idea is to run Graphify once (or whenever the code changes significantly) to produce a knowledge graph that captures file relationships, imports, and functional boundaries. After the graph exists, a tiny directive placed in `CLAUDE.md` instructs Claude to query that graph first, falling back to raw file reads only when explicitly requested.  

The tutorial is split into three practical phases: (1) installing the open‑source Graphify package, (2) optionally visualising the generated markdown graph with Obsidian, and (3) wiring the `CLAUDE.md` file so Claude automatically leverages the graph at session start. By the end of the walkthrough, the reader can reduce token consumption dramatically—up to two orders of magnitude—because Claude now works with a compact, structured index rather than scanning entire source files for every prompt.  

## 2. Why It Matters  
Large language model (LLM) coding assistants are token‑hungry; each time they need to understand a function they must read the whole file and its dependencies, inflating cost and latency. Graphify’s pre‑computed graph acts as a high‑density map, delivering only the nodes relevant to a query. This yields three strategic benefits:  

1. **Cost Efficiency** – Token usage scales with the logical complexity of the request instead of the raw size of the repository, delivering up to ~70× savings on big projects.  
2. **Speed & Responsiveness** – Claude can locate the needed artifact instantly via graph lookup, cutting down the round‑trip time for each prompt.  
3. **Consistency Across Sessions** – Because the graph persists, the assistant no longer re‑reads unchanged files, ensuring stable context and reducing the chance of drift between sessions.  

In modern AI‑augmented development pipelines, where continuous prompting is common, these gains translate directly into faster iteration cycles and lower operational spend.

## 4. Key Concepts & Principles  

- **Knowledge Graph Indexing** – Transforming a collection of source files into a node‑edge structure that records file hierarchy, import relationships, and functional groupings, enabling rapid semantic lookup.  
- **Token Economy** – Understanding how LLMs charge per token and why compressing context into a graph reduces the number of tokens needed for each interaction.  
- **Prompt‑Driven Context Switching** – Using a small instruction set in `CLAUDE.md` to force the model to query the graph before falling back to raw file reads, thereby controlling the flow of information.  
- **Visual Feedback Loop** – Leveraging Obsidian’s graph view to audit the generated knowledge graph, spot high‑dependency clusters, and validate that the indexing aligns with developer expectations.  

## 5. Tools & Technologies Mentioned  

- **Graphify (Python package)** – An open‑source utility that scans a directory, parses files, and emits a markdown‑based knowledge graph. Installable via `pip`.  
- **Claude Code** – The LLM‑driven coding environment that reads `CLAUDE.md` at session start and can execute `/graphify query` commands.  
- **Obsidian** – A markdown vault application that renders the graph output from Graphify, providing an interactive visual map of the codebase.  
- **Python 3.10+** – Minimum interpreter version required for Graphify; ensures compatibility with modern type‑hinting and parsing libraries.  

## 6. Practical Use Cases & Workflows  

### Use Case 1 – One‑Time Project Indexing for Large Repos  
1. **Prepare environment** – Verify Python 3.10+ (`python3 --version`).  
2. **Install Graphify** – Run `pip install graphifyy && graphify install`.  
3. **Generate the graph** – From the root of the Claude project, execute `graphify run`. Wait for the indexing pass (time grows with repo size).  
4. **Persist the map** – The command creates a `graphify-out/` directory containing markdown files that encode the graph.  

### Use Case 2 – Integrating the Graph into Claude Sessions  
1. **Edit `CLAUDE.md`** – Add a block under a `## Context Navigation` heading that (a) forces a graph query (`/graphify query "<question>"`), (b) restricts raw file reads to explicit commands, and (c) points Claude to `graphify-out/wiki/index.md` as the navigation root.  
2. **Start a Claude session** – The assistant automatically loads the new instructions and will first consult the graph for any context‑related request.  
3. **Optional visual audit** – Open the same folder in Obsidian, enable Graph View (`Cmd+G` / `Ctrl+G`), and inspect node clusters to understand dependency hotspots.  

Both workflows can be repeated whenever the codebase undergoes substantial changes (e.g., after a major refactor).
