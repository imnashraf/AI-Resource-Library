## 1. What This Resource Teaches  
This guide explains how to transform a single‑model interaction into a structured “council” that forces an LLM to confront a problem from multiple, deliberately contrasting perspectives. By issuing a single, multi‑stage prompt to Claude (or any comparable chat model), the user obtains five distinct advisory outputs, an anonymous peer‑review of those outputs, and a concise synthesis from a designated “chairman.” The methodology hinges on role‑playing: each advisor adopts a fixed mental model (contrarian, first‑principles, expansionist, outsider, executor) and must answer without hedging. After the answers are shuffled and relabeled, the model critiques them blind, surfacing the strongest argument, the biggest blind spot, and any collective omission. Finally, the chairman distills a single recommendation, the core rationale, and an actionable next step.  

Beyond the prompt mechanics, the article contrasts the single‑model pitfall—over‑agreeability and echo‑chamber bias—with the council’s ability to surface failure modes, hidden opportunities, and pragmatic actions. It also outlines a more elaborate multi‑model variant (Karpathy’s open‑source repo) that distributes the advisors across different providers (GPT, Claude, Gemini, Grok) via OpenRouter, but emphasizes that the Claude‑only version already captures the bulk of the benefit without any code.

## 2. Why It Matters  
In practice, LLMs are tuned to be helpful and tend to reinforce the user’s framing, which can mask critical flaws in strategy, product design, or decision‑making. The council architecture injects systematic dissent and cross‑validation, turning a passive assistant into a miniature advisory board. This yields three strategic advantages:  

1. **Risk mitigation** – the contrarian surface‑checks failure points that a single model would gloss over.  
2. **Idea expansion** – the expansionist and outsider lenses surface growth avenues and blind spots that insiders routinely miss.  
3. **Actionability** – the executor condenses the discussion into a concrete, near‑term deliverable, accelerating execution cycles.  

Adopting this pattern reduces the need for manual “second‑opinion” prompting, shortens iteration loops, and improves the robustness of high‑stakes decisions (e.g., product pivots, hiring plans, pricing strategies). It also democratizes a form of peer review that previously required multiple human experts or a suite of API calls.

## 4. Key Concepts & Principles  

- **Advisor Role‑Playing**: Each of the five personas is defined by a single guiding question (e.g., “What will fail?”). The model must stay in character, producing a decisive answer without qualifiers. This forces the LLM to explore a narrow, high‑signal line of reasoning.  

- **Anonymous Peer Review**: After generation, the five outputs are relabeled (A‑E) and shuffled. The model then critiques them as a neutral reviewer, identifying the strongest argument, the most glaring omission, and any collective blind spot. This step eliminates bias that would arise from knowing which persona produced each answer.  

- **Chairman Synthesis**: A final “chairman” voice reads the peer‑review and produces a succinct recommendation, a single supporting rationale, and a concrete next action. The output is deliberately limited to ~200 words to keep the decision digestible.  

- **Prompt‑Driven Orchestration**: All three stages are encoded in a single, long prompt. The structure, not the number of distinct models, drives the multi‑stage workflow. The prompt must be fed to the longest‑thinking variant of Claude (e.g., Sonnet 4.5 or Opus) to allow sufficient reasoning depth.  

## 5. Tools & Technologies Mentioned  

- **Claude (claude.ai)** – The primary chat interface used to run the entire council in a single conversation. The guide recommends the most capable model variant for maximal token budget.  
- **OpenRouter** – An aggregation API that provides unified access to multiple LLM providers (GPT, Gemini, Grok, etc.). Required only for Karpathy’s multi‑model implementation.  
- **Git & uv** – For cloning and managing the Python environment of the open‑source `llm‑council` repository. `uv` is a modern alternative to `pip`/`conda` for dependency isolation.  

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Strategic Decision Validation (Claude‑Only)  
1. Open a fresh Claude chat window to avoid context leakage.  
2. Paste the full council prompt verbatim.  
3. Replace the placeholder with a concrete decision question, e.g., “Should we pivot our SaaS product to a subscription‑first model?”  
4. Submit the prompt and wait for the model to output all three stages.  
5. Read the chairman’s recommendation first; then review each advisor’s reasoning if deeper insight is needed.  

### Use Case 2 – Multi‑Model Council via Karpathy’s Repo  
1. Obtain an OpenRouter API key from `openrouter.ai`.  
2. Clone the repository:  
   ```bash
   git clone https://github.com/karpathy/llm-council.git
   cd llm-council
   ```  
3. Install dependencies with `uv`:  
   ```bash
   uv venv
   uv pip install -r requirements.txt
   ```  
4. Edit `backend/config.py` to select the desired models for each advisor and set the chairman (default: GPT, Claude, Gemini, Grok; Gemini chairs).  
5. Launch the local server:  
   ```bash
   uv run python -m backend.main
   ```  
6. Open the React frontend (usually `http://localhost:3000`) and submit your question. The backend will dispatch parallel calls to the configured models, aggregate the responses, perform the anonymous review, and display the chairman’s synthesis.  

## 7. Prerequisites  

- An active Claude account (or equivalent chat model with a long‑context variant).  
- For the single‑model workflow: no code, just a web browser.  
- For the multi‑model workflow: basic command‑line proficiency, Git, Python 3.10+, `uv` (or `pip`), and an OpenRouter API key.  
- Understanding of prompt engineering fundamentals (system messages, role instructions, token budgeting).
