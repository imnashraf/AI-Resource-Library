## 1. What This Resource Teaches
This guide introduces a specific workflow optimization for Claude Code known as "GrillMe," a skill designed to mitigate the "vague prompt" problem in AI-assisted development. The core educational objective is to shift the interaction paradigm from passive code generation to active requirement elicitation. Instead of allowing the AI agent to infer missing context through confident guessing, the GrillMe skill forces the agent to conduct a structured interview with the user before writing any code. This transforms the initial phase of development from a trial-and-error process into a deliberate alignment exercise.

Technically, the resource explains that GrillMe is not a complex framework or API integration, but rather a lightweight Markdown-based instruction set (a "skill") that modifies the agent's behavior. It teaches users how to install and configure this skill within the `.claude` directory of their project. The guide details the internal logic of the skill: it mandates that the agent asks questions one at a time, provides its own recommended answer for each question to facilitate decision-making, and autonomously explores the existing codebase to answer questions that can be resolved via static analysis rather than user input.

Architecturally, the guide positions this approach as a solution to the "misalignment gap" between human intent and machine execution. It outlines a four-stage flow: brief description, invocation of the grilling session, iterative Q&A resolution, and final plan locking. By the end of the session, the user has a comprehensive, gap-free specification that the agent can execute with high fidelity, effectively replacing hours of iterative rework with a single, focused upfront conversation.

## 2. Why It Matters
In modern AI-assisted development, the primary bottleneck is often not the speed of code generation, but the accuracy of the generated code relative to user intent. The "GrillMe" methodology addresses this by introducing intentional friction at the start of a task. This friction is strategic: it prevents the agent from baking incorrect assumptions into the codebase, which are expensive and difficult to refactor later. The guide highlights that a 15–45 minute investment in a grilling session can save several hours of debugging and re-implementing features that were built based on misinterpreted requirements.

The strategic value lies in the shift from "prompt engineering" as a one-shot event to "context engineering" as a collaborative process. By forcing the agent to articulate its assumptions and seek confirmation, the workflow ensures that complex design decisions, dependencies, and edge cases are resolved explicitly. This is particularly critical for architecture-level changes or new feature development where the decision tree is broad. The method also leverages the agent's ability to read code, ensuring that the interview remains focused on high-level design choices rather than low-level factual queries that the agent could answer itself.

Furthermore, this approach standardizes the handoff between human planning and machine execution. It creates a "locked" plan that serves as a single source of truth, reducing the cognitive load on the developer who no longer needs to constantly monitor and correct the agent's direction mid-stream. It transforms the AI from a junior developer who guesses into a senior consultant who clarifies before acting.

## 4. Key Concepts & Principles
- **The Misalignment Gap**: The fundamental problem where the user's internal mental model of a feature is more complex and nuanced than the brief written prompt. AI agents, lacking the ability to ask clarifying questions by default, fill this gap with statistical assumptions, leading to confident but incorrect outputs.
- **Structured Elicitation (Grilling)**: A methodology where the AI agent acts as an interviewer, systematically walking through the design tree of a project. This involves resolving dependencies between decisions one by one, ensuring that no branch of the design logic is left unaddressed before implementation begins.
- **Recommendation-First Interaction**: A UX principle for AI interaction where the agent does not just ask open-ended questions ("What should we do?") but proposes a specific solution ("I recommend X because Y. Do you agree?"). This reduces user cognitive load, speeds up decision-making, and prevents the conversation from stalling.
- **Codebase-Aware Questioning**: The principle that the agent should leverage its ability to read the repository to answer factual questions. If a piece of information (e.g., variable names, existing function signatures) can be found via code exploration, the agent should do so rather than asking the user, reserving the interview for high-level design and intent.

## 5. Tools & Technologies Mentioned
- **Claude Code**: The primary execution environment. It is an agentic coding tool that reads instructions from local Markdown files (skills) and executes them within the terminal. It supports the `/grill-me` command and other custom skills.
- **Matt Pocock's Skills Repository (`mattpocock/skills`)**: A public GitHub repository containing the source code for the GrillMe skill and other productivity skills. It serves as the distribution channel for these Markdown-based instruction sets.
- **Markdown Skill Files**: The technical format for the skills. These are simple `.md` files (e.g., `SKILL.md`) placed in the `.claude` directory that contain natural language instructions for the AI agent. They are lightweight, version-controllable, and easily customizable.
- **Issue Trackers (GitHub, Linear, Local Files)**: External systems that the skills can integrate with. For example, the `/to-prd` skill can publish the results of a grilling session directly to an issue tracker, bridging the gap between conversational planning and project management.

## 6. Practical Use Cases & Workflows
- **Workflow: Implementing a New Complex Feature**
    1.  **Setup**: Ensure the `mattpocock/skills` repository is installed in the project's `.claude` directory.
    2.  **Initiation**: Open Claude Code in the project root. Briefly describe the new feature (e.g., "I want to add a user authentication system").
    3.  **Invocation**: Type `/grill-me`.
    4.  **Execution**: The agent begins asking questions one at a time. For each question, it provides a recommended answer (e.g., "I recommend using JWT for stateless auth. Do you agree?").
    5.  **Codebase Check**: If the agent asks about existing database schemas, it will first scan the codebase. If it finds the schema, it will state its findings rather than asking.
    6.  **Resolution**: The user answers 16–50 questions, refining the plan.
    7.  **Implementation**: Once the plan is locked, the agent proceeds to write code based on the fully resolved specification.

- **Workflow: Converting a Grilling Session into a PRD**
    1.  **Grilling**: Conduct a standard `/grill-me` session to clarify requirements for a new module.
    2.  **Synthesis**: After the session, invoke the `/to-prd` skill.
    3.  **Output**: The agent synthesizes the conversation history into a formal Product Requirements Document (PRD).
    4.  **Integration**: The agent publishes this PRD to the configured issue tracker (e.g., GitHub Issues or Linear), creating a trackable ticket for the development team.
