## 1. What This Resource Teaches
This resource outlines a strategic extension of the Claude Code terminal agent by integrating five specialized plugins that address specific limitations of Large Language Models (LLMs) in autonomous coding environments. The core pedagogical objective is to transition from "vibe coding"—where the AI guesses based on training data—to "verified coding," where the AI interacts with live systems to validate its output. The guide demonstrates how to bridge the gap between static text generation and dynamic system interaction by providing direct connections to databases, security scanners, browser automation engines, design extraction tools, and live documentation sources.

Architecturally, the resource focuses on the "Agent Skill" and "MCP (Model Context Protocol)" paradigms. It teaches that an LLM’s intelligence is bounded by its context window and training cutoff; therefore, augmenting the agent with external tools that provide real-time state (such as current database schemas or live DOM structures) significantly reduces hallucination rates. The workflow emphasizes a modular approach where each plugin solves a distinct class of error: schema mismatch (Supabase), security vulnerability (Strix), visual/layout failure (Playwright), stylistic inconsistency (SkillUI), and API obsolescence (Context7).

## 2. Why It Matters
In modern AI-assisted development, the primary bottleneck is no longer code generation speed but verification accuracy. Without these integrations, developers must manually cross-reference AI-generated code against live environments, which negates the efficiency gains of AI coding. This resource matters because it automates the verification loop. By allowing the AI to "see" its own output (via screenshots), "test" its own security (via pentesting agents), and "read" its own database state, the developer shifts from a manual debugger role to a high-level architect role.

Strategically, this approach reduces technical debt accumulation. AI models often generate code that is syntactically correct but semantically broken due to outdated library versions or incorrect assumptions about backend state. By integrating live documentation and database introspection, the workflow ensures that the generated code is not just plausible, but actually functional within the specific constraints of the project. This is critical for production-ready applications where subtle errors in authentication flows or data integrity can lead to significant security or operational failures.

## 4. Key Concepts & Principles
- **Agentic Tool Interop (MCP & Skills)**: The principle that LLMs should not rely solely on internal weights for factual or state-based information. Instead, they should be equipped with tools (via MCP servers or agent skills) that allow them to query external systems (databases, browsers, doc servers) in real-time. This transforms the LLM from a static text predictor into a dynamic system operator.
- **Closed-Loop Verification**: The workflow principle where the AI generates code, then immediately uses a tool to test that code (e.g., running Playwright to screenshot the UI, or Strix to attempt an exploit). The feedback from the tool is fed back into the context, allowing the AI to self-correct without human intervention.
- **Contextual Grounding via Live Data**: Addressing the "stale knowledge" problem by injecting live, version-specific data into the prompt context. For example, using Context7 to pull current API documentation ensures the AI does not hallucinate deprecated methods, and using Supabase to read the actual schema prevents column name mismatches.
- **Design System Extraction as Code**: The concept that visual design is not just an aesthetic choice but a structured data set (colors, spacing, typography) that can be programmatically extracted and enforced. By converting a website's design into a machine-readable skill file, the AI can maintain visual consistency without requiring the developer to manually describe CSS variables.

## 5. Tools & Technologies Mentioned
- **Claude Code**: The primary terminal-based AI agent. It serves as the orchestrator that interprets user prompts, executes commands, and utilizes the installed plugins/skills to perform complex tasks.
- **Supabase**: A backend-as-a-service platform. In this context, it is used via a plugin to allow the AI to execute SQL queries, manage migrations, and generate TypeScript types directly from the live database schema, ensuring data layer accuracy.
- **Strix**: An open-source AI-powered penetration testing tool. It acts as an adversarial agent that attempts to exploit vulnerabilities (SQLi, XSS, IDOR) in the codebase, providing proof-of-concept exploits to validate security fixes.
- **Playwright CLI**: A browser automation framework. It enables the AI to launch a headless or headed browser, navigate through the application, interact with UI elements, and capture screenshots/console logs, providing visual and functional feedback.
- **SkillUI**: A static analysis tool that crawls websites to extract design tokens (colors, fonts, spacing). It packages these into a `CLAUDE.md` or `SKILL.md` file, allowing the AI to replicate a specific design system in new code generation.
- **Context7**: An MCP server that provides access to live, version-matched documentation for thousands of libraries. It ensures the AI references current API signatures and best practices rather than relying on potentially outdated training data.

## 6. Practical Use Cases & Workflows
- **Automated UI Regression Testing**:
    1.  Install Playwright CLI and register it as a skill for Claude Code.
    2.  Prompt the AI: "Test the sign-up flow on localhost:3000. Take screenshots of every step and flag any layout issues or console errors."
    3.  The AI launches a browser, executes the user journey, captures visual evidence, and analyzes the screenshots for broken layouts or missing elements.
    4.  The AI reports specific bugs (e.g., "Button overlaps text on mobile view") and suggests CSS fixes, which it can then implement and re-test.

- **Secure Database Schema Evolution**:
    1.  Install the Supabase plugin and connect it to the project’s environment variables.
    2.  Prompt the AI: "Add a 'last_login' timestamp to the users table and generate the corresponding TypeScript interface."
    3.  The AI queries the live database to confirm the current schema, writes the migration SQL, executes it, and then reads the updated schema to generate accurate type definitions.
    4.  This prevents errors caused by the AI guessing column names or types that do not exist in the production environment.

- **Design-Consistent Feature Development**:
    1.  Run `skillui --url <competitor_or_brand_site>` to extract the design system.
    2.  Open the generated folder in Claude Code, which automatically loads the design tokens into context.
    3.  Prompt the AI: "Build a new pricing page that matches the extracted design system."
    4.  The AI uses the specific hex codes, font families, and spacing scales from the skill file to generate CSS/Tailwind classes, ensuring the new page visually aligns with the existing brand without manual styling instructions.
