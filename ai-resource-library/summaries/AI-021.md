## 1. What This Resource Teaches  
This guide walks a developer through turning a static landing page into a data‑driven, self‑optimising asset by coupling PostHog’s open‑source analytics suite with Claude Code’s AI‑assisted code generation. It starts with the creation of a free PostHog project, then shows how Claude Code can automatically detect the site’s technology stack (plain HTML, React, Next.js, etc.) and inject the appropriate tracking snippet without manual edits.  

Beyond basic page‑view collection, the tutorial demonstrates how to define custom events—button clicks, scroll milestones, form submissions, and outbound link clicks—so that the analytics platform records the exact user interactions that matter for conversion. Once the data pipeline is live, Claude is configured as an “analytics advisor” that queries the PostHog API, surfaces drop‑off points, conversion funnels, and performance metrics, and then emits ready‑to‑paste Claude Code prompts that implement the suggested UI changes.  

Finally, the material explains how to spin up an A/B experiment using PostHog feature flags: two hero‑section variants are served in a 50/50 split, clicks on the primary call‑to‑action are logged as the conversion metric, and the experiment results are visualised in PostHog’s Experiments dashboard. The entire workflow is designed to be repeatable, allowing continuous iteration based on real‑time analytics without writing additional instrumentation code.  

## 2. Why It Matters  
Embedding analytics directly into the development loop eliminates the latency between data collection and insight generation. By leveraging Claude Code, teams can automate the otherwise tedious steps of installing SDKs, wiring custom events, and updating UI elements, freeing engineers to focus on product strategy. The free tier of PostHog provides a privacy‑first alternative to heavyweight SaaS trackers, making it suitable for startups or projects with strict data‑governance requirements.  

The combination of AI‑driven code assistance and feature‑flag‑based experimentation creates a rapid‑feedback loop: hypotheses are formed by Claude’s data‑backed recommendations, implemented instantly via generated code, and validated through split testing. This reduces the time‑to‑value for conversion optimisation, improves experiment rigor (because the same analytics pipeline powers both observation and decision), and scales gracefully as traffic grows.

## 4. Key Concepts & Principles  

- **Event‑Centric Instrumentation**: Moving from generic page‑view logs to granular, named events (e.g., `cta_click`, `form_scroll_50`) that capture user intent and enable funnel analysis.  
- **AI‑Assisted Code Generation**: Claude Code parses the repository, selects the correct PostHog SDK (JavaScript, npm module, etc.), injects initialization code, and later produces precise patches for UI changes based on analytics feedback.  
- **Feature‑Flag‑Driven Experimentation**: PostHog’s feature flags act as a traffic router, assigning visitors to control or variant groups at runtime, ensuring a statistically sound split test without deploying separate code branches.  
- **Closed‑Loop Optimization**: Claude continuously queries the PostHog API, interprets metrics (conversion rates, drop‑off percentages), and outputs implementation prompts, creating an automated feedback cycle from data to deployment.

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Auto‑Instrument a New Landing Page  
1. **Create a PostHog project** and copy the generated API key (`phc_…`).  
2. **Open the landing‑page repository** in Claude Code.  
3. **Prompt Claude** with a request to research and install PostHog for the detected stack.  
4. Claude adds the SDK import, initializes it with the API key, and verifies that a test click appears in the Live Events view.  
5. **Result:** The page now streams raw interaction data to PostHog without manual code edits.  

### Use Case 2 – Continuous Conversion Optimization Loop  
1. **Define custom events** (button clicks, scroll depth milestones, form submissions) via a Claude Code prompt that specifies property names and event labels.  
2. **Validate** that each interaction surfaces in the PostHog dashboard.  
3. **Activate Claude as an analytics advisor** by feeding a system prompt that instructs it to pull live metrics and generate actionable recommendations.  
4. **Ask Claude** questions such as “Which CTA has the lowest click‑through?” or “Where do users abandon the form?”  
5. **Claude returns** a concise Claude Code snippet (e.g., change button text, move form field) that you paste back into the repository.  
6. **Deploy** the change; the updated event data flows back into PostHog, closing the loop.  

### Use Case 3 – A/B Test Hero Section Copy  
1. **Prompt Claude** to create a feature‑flag‑based split test: keep the existing hero as control, generate a variant with alternate headline/CTA text.  
2. Claude adds the feature flag definition, wraps the hero component in a conditional render, and configures the flag to split traffic evenly.  
3. **Set the primary CTA click** as the conversion metric in PostHog’s Experiments UI.  
4. **Monitor** the experiment; once statistical significance is reached, instruct Claude to promote the winning variant to the default rendering.
