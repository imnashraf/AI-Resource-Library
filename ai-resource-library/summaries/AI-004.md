## 4. Key Concepts & Principles  

- **Projects as Persistent Context Containers** – A Project bundles a set of instructions, uploaded reference files (brand guides, templates, pricing tables), and a default model. When you open a chat inside a Project, Claude automatically inherits this context, eliminating the need to restate background information.  

- **Explicit Memory Management** – Users can issue “remember” or “forget” commands to store facts globally. This is distinct from Project‑level instructions and applies across all workspaces, enabling a personal knowledge base that the model consults before responding.  

- **Skills as Reusable Prompt Packages** – A Skill encapsulates a deterministic prompt template plus post‑processing rules for a specific task (e.g., converting data to a DOCX, generating a PowerPoint outline). Once defined, the Skill can be invoked with a single command, guaranteeing consistent output without re‑typing the same prompt each time.  

- **LLM Council Decision Engine** – By spawning multiple “advisor” personas (Contrarian, First‑Principles, Expansionist, Outsider, Executor) and having them critique each other, the Council surfaces hidden assumptions and converges on a single, ranked recommendation. This mitigates Claude’s default helpful‑but‑agreeable bias.  

- **Connectors for Live Data Interaction** – MCP connectors bridge Claude to external services (Gmail, Google Calendar, Drive, Notion, Slack). They allow Claude to read real‑time information and draft actions (e.g., email replies) while keeping the user in control of final execution.  

- **Scheduled Claude Code Automations** – Claude Code lets you write lightweight scripts that run on a timer, invoke Skills, and interact with connectors. Typical patterns include hourly lead‑response generation, nightly report compilation, and daily agenda summarization.  

- **Model Tier Matching** – Opus (the most capable model) should be reserved for tasks requiring deep reasoning or long‑form composition, while lighter models (Claude‑3‑Haiku, etc.) are sufficient for routine data extraction or template filling, optimizing cost per token.  

## 5. Tools & Technologies Mentioned  

- **Claude (Anthropic’s conversational LLM)** – The core language model that powers all interactions, accessible via web UI, API, or Claude Code.  
- **Claude Code** – A low‑code scripting environment within Claude that supports scheduled jobs, conditional logic, and connector calls. Ideal for building repeatable automations without external infrastructure.  
- **MCP Connectors** – Pre‑built integrations that expose Gmail, Google Calendar, Google Drive, Notion, Slack, and other SaaS APIs to Claude. They enable read/write operations on user data when explicitly invoked.  
- **Skill Library** – A repository of custom prompt bundles (e.g., “Create a DOCX from markdown”, “Generate a PowerPoint deck”) that can be shared across Projects.  
- **LLM Council Prompt Templates** – Structured prompts that instantiate the five advisor personas and orchestrate their peer‑review cycle.  

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Consistent Brand‑Aligned Content Production  
1. **Create a “Content” Project** and upload the brand style guide, tone‑of‑voice examples, and a list of prohibited phrasing.  
2. Define a **Skill** called `WriteBlogPost` that accepts a headline and a keyword list, then injects the brand guide rules into the prompt.  
3. In the Project chat, invoke `WriteBlogPost` with the desired topic. Claude returns a draft that already respects sentence length limits, avoids banned words, and follows the British‑English style.  
4. If the output deviates, edit the draft, note the correction, and update the Skill’s rule set (e.g., “Never start with ‘In today’s world’”).  
5. Re‑use the Skill for every new article, guaranteeing uniformity without re‑prompting.  

### Use Case 2 – Automated Lead‑Response Pipeline  
1. **Enable the Gmail connector** and grant read‑only access to the inbox and draft‑write permission.  
2. Write a Claude Code script `LeadResponder` that runs every hour:  
   ```python
   leads = gmail.search("label:lead-unreplied newer_than:1d")
   for mail in leads:
       reply = skill.invoke("DraftLeadReply", {
           "sender_name": mail.from_name,
           "company": mail.subject,
           "tone": "friendly"
       })
       gmail.create_draft(to=mail.from, subject=mail.subject, body=reply)
   ```  
3. Deploy the script as a scheduled task. Claude drafts a personalized reply for each new lead and saves it as a draft for quick human approval.  
4. After a week, review the drafts, capture any recurring phrasing issues, and feed those back into the `DraftLeadReply` Skill to improve future drafts.
