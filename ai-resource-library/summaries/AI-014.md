## 1. What This Resource Teaches  
This guide walks a developer through installing and activating Ruflo, an open‑source orchestration layer that runs dozens of specialized agents inside Claude Code. It explains how to bootstrap the framework with a single wizard, register Ruflo as a Claude Code MCP (Model‑Centric Plugin) server, and launch the background daemon that continuously learns from successful runs.  

Beyond the mechanics of installation, the material details Ruflo’s three‑tier routing logic: trivial transformations are handled by a WebAssembly kernel (no LLM cost), medium‑complexity jobs are delegated to a low‑price Claude model, and only the most demanding decisions invoke the premium Opus model. By exposing 313 pre‑packaged MCP tools, the framework enables automatic task delegation without the user needing to master each tool individually.  

Finally, the document provides optional commands for manually constructing a “swarm” of agents with a hierarchical topology, useful for long‑running builds or when fine‑grained control over agent composition is required.

## 2. Why It Matters  
Ruflo tackles two pain points that are common in modern AI‑augmented development environments: **scalability** and **cost efficiency**. By parallelizing over 60 specialist agents, developers can keep many subtasks (coding, testing, security scanning, review, etc.) active simultaneously, dramatically shortening feedback loops. The intelligent routing layer reduces Claude API spend by up to three‑quarters because most routine transformations never invoke a language model.  

In addition, the self‑learning daemon captures successful execution patterns and refines routing decisions over time, meaning the system becomes more accurate and cheaper the longer it runs. For teams already invested in Claude Code, Ruflo offers a plug‑and‑play extension that unlocks enterprise‑grade multi‑agent capabilities without additional licensing fees.

## 4. Key Concepts & Principles  

- **Three‑Tier Model Routing**: A decision engine that classifies incoming work into “simple”, “mid‑level”, or “complex”. Simple tasks are processed by a WebAssembly kernel (zero LLM cost), mid‑level tasks are sent to a cheaper Claude model, and only truly complex decisions trigger the high‑performance Opus model.  

- **Self‑Learning Daemon**: A persistent background service that records successful task‑agent pairings, updates routing heuristics, and gradually improves both accuracy and cost‑effectiveness without manual intervention.  

- **MCP (Model‑Centric Plugin) Integration**: Ruflo registers itself as an MCP server inside Claude Code, exposing 313 ready‑to‑use tools. This registration enables Claude to invoke any tool via a unified API, eliminating the need for explicit prompting.  

- **Manual Swarm Construction**: While the default automatic routing suffices for most projects, Ruflo also supports explicit creation of a coordinated swarm with a defined topology (e.g., hierarchical) and a capped number of agents, giving developers deterministic control over parallelism.

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Rapid Project Bootstrapping  
1. **Create a workspace**: `mkdir my‑project && cd my‑project`.  
2. **Run the wizard**: `npx ruflo@latest init --wizard` (or `bunx …` for Bun). The wizard scaffolds configuration files (`CLAUDE.md`, settings) and installs the 313 MCP tools.  
3. **Register MCP**: `claude mcp add ruflo -- npx -y ruflo@latest mcp start`. Verify with `claude mcp list`.  
4. **Health check**: `npx ruflo doctor --fix` to auto‑repair any missing dependencies.  
5. **Start learning daemon**: `npx ruflo daemon start`. The daemon now runs in the background, collecting routing data.  
6. **Open Claude Code** and work as usual; Ruflo silently routes each request to the appropriate specialist agent.  

### Use Case 2 – Controlled Parallel Build with a Manual Swarm  
1. **Initialize a hierarchical swarm**: `npx ruflo swarm init --topology hierarchical --max-agents 8 --strategy specialized`.  
2. **Spawn dedicated agents**:  
   - `npx ruflo agent spawn -t coder --name build‑coder`  
   - `npx ruflo agent spawn -t tester --name build‑tester`  
   - `npx ruflo agent spawn -t reviewer --name build‑reviewer`  
   - `npx ruflo agent spawn -t security --name build‑sec`  
3. **Trigger the build** (e.g., via a Claude Code command or script). The swarm coordinates the agents, each handling its domain in parallel.  
4. **Monitor**: Use `npx ruflo doctor --fix` to inspect health, and `npx ruflo daemon stop` when the build completes.
