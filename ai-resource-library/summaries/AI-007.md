## 1. What This Resource Teaches  
This guide walks the reader through the end‑to‑end creation of a **Claude Routine**, a cloud‑hosted automation construct that couples a natural‑language prompt with direct access to GitHub repositories and a suite of service connectors. Unlike traditional pipeline tools that execute a static series of nodes, a Routine lets Claude interpret the current context, make decisions, and produce varied outcomes on each invocation.  

The material explains how to define the four pillars of a Routine—prompt, repository list, environment (including secrets and pre‑run scripts), and connectors—then select one of three trigger modalities (scheduled cron‑style, GitHub event‑driven, or on‑demand API call). It also details the operational limits (run caps per plan, minimum hourly cadence, branch‑write safeguards) and security considerations such as one‑time bearer tokens for API triggers.  

By the end of the article, a practitioner can spin up a fully‑functional Routine from the web UI, desktop client, or CLI, configure it to react to code changes or time‑based events, and integrate it with Slack, Linear, Gmail, or Google Calendar for downstream notifications.

## 2. Why It Matters  
Claude Routines shift automation from **static orchestration** to **context‑aware AI execution**. Because the logic lives on Anthropic’s infrastructure, teams no longer need to maintain cron jobs, CI agents, or self‑hosted workers; the routine persists indefinitely and scales automatically. This reduces operational overhead, eliminates “forgotten” cron jobs, and provides a single source of truth for AI‑driven policies (e.g., security review checklists).  

In modern development pipelines, rapid feedback loops are critical. Routines can instantly react to pull‑request events, enforce labeling conventions, or generate on‑the‑fly reports, thereby accelerating triage, improving code quality, and freeing human reviewers to focus on higher‑level design concerns. The ability to invoke a Routine via a simple HTTP POST also makes it a natural extension point for monitoring systems, CD pipelines, or internal dashboards.

## 4. Key Concepts & Principles  

- **Routine Definition**: A composite object consisting of a natural‑language instruction set, a list of GitHub repositories, an optional environment block (variables, pre‑run scripts), and a collection of service connectors. The prompt drives Claude’s reasoning each time the Routine fires.  

- **Trigger Modalities**:  
  1. **Schedule** – Recurring execution based on hourly, daily, weekday, weekly, or custom cron expressions (minimum granularity: one hour).  
  2. **GitHub Event** – Real‑time activation when a selected repository event occurs (e.g., PR opened, merged, release published).  
  3. **API Call** – Immediate fire via a unique endpoint secured with a bearer token, allowing any external system to invoke the Routine.  

- **Connector Ecosystem**: Pre‑built adapters that expose external services (Slack, Linear, Gmail, Google Calendar, GitHub) to Claude. Connectors enable the Routine to post messages, create tickets, send emails, or manipulate repository objects without custom code.  

- **Safety & Limits**: Routines are sandboxed to write only to branches prefixed with `claude/` unless explicitly relaxed, protecting mainline code. Plan tiers impose daily run caps (5‑25 runs) and enforce a minimum schedule interval of 60 minutes. API tokens are displayed only once and must be stored securely.

## 5. Tools & Technologies Mentioned  

- **Claude Code** – Anthropic’s web‑based IDE where Routines are authored, edited, and inspected. It hosts the execution environment and provides the UI for trigger configuration.  
- **GitHub** – Source‑code platform that supplies repositories for read/write access and emits webhook‑style events that can launch a Routine.  
- **Connectors (Slack, Linear, Gmail, Google Calendar)** – Ready‑made integrations that let Claude interact with communication, issue‑tracking, and calendar services.  
- **cURL / HTTP Client** – Command‑line utility used to POST to the Routine’s API endpoint, demonstrating how external systems can trigger a Routine programmatically.  

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Nightly Issue Triage (Schedule Trigger)  
1. **Create Routine** in the Claude web UI, selecting “Schedule” as the trigger and configuring a daily run at 08:00 local time.  
2. **Prompt**: Instruct Claude to fetch all newly opened GitHub issues, apply label heuristics based on keywords, assign owners from a predefined mapping, and compose a Slack digest.  
3. **Repositories**: Add the target repo(s) where issues reside.  
4. **Connectors**: Enable GitHub (for issue mutation) and Slack (for the digest).  
5. **Environment**: Store any API keys (e.g., Slack bot token) as environment variables.  
6. **Save** – Claude will automatically clone the repo, run the prompt logic, push label changes, and post the summary each night.  

### Use Case 2 – On‑Demand Deploy Verification (API Trigger)  
1. **Define Routine** with an API trigger; capture the generated endpoint URL and one‑time bearer token. Store the token in a CI secret store (e.g., GitHub Actions `secrets.ROUTINE_TOKEN`).  
2. **Prompt**: Tell Claude to accept a JSON payload containing `deploy_id` and `environment`, run smoke tests against the new deployment, scan logs for regressions, and post a “go/no‑go” message to a release channel.  
3. **Connectors**: Add GitHub (to fetch logs or open a verification PR) and Slack (to broadcast the result).  
4. **CI Integration** – In a GitHub Actions workflow, add a step:  

   ```yaml
   - name: Trigger Claude Routine
     env:
       ROUTINE_URL: ${{ secrets.ROUTINE_URL }}
       ROUTINE_TOKEN: ${{ secrets.ROUTINE_TOKEN }}
     run: |
       curl -X POST "$ROUTINE_URL" \
         -H "Authorization: Bearer $ROUTINE_TOKEN" \
         -H "anthropic-beta: experimental-cc-routine-2026-04-01" \
         -H "Content-Type: application/json" \
         -d '{"deploy_id":"v1.2.3","environment":"prod"}'
   ```  

5. **Result** – After the deployment finishes, the Routine runs instantly, performs the checks, and notifies the team without manual intervention.
