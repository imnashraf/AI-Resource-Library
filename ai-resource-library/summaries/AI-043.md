## 1. What This Resource Teaches  

This guide walks the reader through the end‑to‑end construction of a fully automated competitor‑watching service that turns raw social‑media posts into a weekly intelligence brief and ready‑to‑publish content drafts. The core learning outcome is how to stitch together a multi‑layer pipeline—scraping, storage, AI‑driven analysis, gap detection, content generation, and delivery—using a combination of low‑code orchestration (n8n), managed data services (Supabase), third‑party scrapers (Apify), and Anthropic’s Claude models.  

Beyond the technical stack, the material demonstrates a productisation mindset: the system is sold as a managed SaaS‑style offering rather than a one‑off prompt collection. Readers see how to design a repeatable architecture, keep operational costs low through model tiering and batch API calls, and package the solution with clear pricing tiers (setup fee + monthly retainer).  

## 2. Why It Matters  

In a landscape where many agencies rely on manual competitor audits, an automated engine creates a defensible moat. It delivers quantifiable market intelligence every week without human intervention, turning a traditionally labor‑intensive activity into a recurring revenue stream. By normalising data at ingestion and persisting structured analysis, the pipeline enables rapid querying, trend spotting, and content ideation that are far more accurate than guesswork.  

From an AI‑ops perspective, the guide showcases best practices for cost‑effective LLM usage: cheap “filter” models (Claude Haiku) prune low‑value items, while a more capable model (Claude Sonnet) handles the heavy analytical work. Batch requests cut API spend by roughly half, and caching of system prompts guarantees consistent brand voice while avoiding repeated prompt engineering. The result is a scalable, low‑maintenance service that can be replicated across clients and niches.

## 4. Key Concepts & Principles  

- **Layered Pipeline Architecture** – The system is split into six sequential layers (Ingestion → Store → Analyse → Gap Detection → Generate → Deliver). Each layer has a single responsibility, produces a clean JSON contract, and can be unit‑tested in isolation before wiring to the next stage.  

- **Schema‑First Normalisation** – All scraped payloads are mapped to a unified `posts` table at ingest time. This eliminates downstream field‑mapping logic and guarantees that downstream LLM calls receive a predictable structure.  

- **Cost‑Optimised Model Strategy** – Use a cheap model (Claude Haiku) to filter out obvious low‑performers, then feed the remaining items to a higher‑tier model (Claude Sonnet). Batch the weekly analysis calls to leverage the 50 % discount offered by the Claude batch endpoint.  

- **Voice‑Profile Prompt Caching** – Build a static system prompt (`/voice/profile.md`) that captures the client’s tone, preferred phrasing, and prohibited words. Store this prompt in a file or Supabase row and reference it on every generation request, ensuring brand consistency without re‑sending the full prompt each time.

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Deploy a Weekly Competitor‑Intelligence Engine for a SaaS Brand  

1. **Provision Infrastructure** – Spin up a Supabase project, enable the Postgres database, and create an API key.  
2. **Configure n8n** – Install n8n on Railway or a VPS, add environment variables for Apify, Supabase, and Anthropic keys.  
3. **Create the Posts Table** – Run the supplied SQL migration (see Section 4) via Supabase SQL editor.  
4. **Set Up Scrapers** – In n8n, add two *Apify Run Actor* nodes (Instagram & TikTok) with the client’s competitor handles as input. Enable “wait for finish”.  
5. **Normalise & Upsert** – Use a *Code* node (JavaScript) to map actor output to the unified schema, then call Supabase’s `upsert` endpoint.  
6. **Batch Analyse** – Invoke Claude’s batch endpoint with the week’s new rows, passing a JSON schema that forces output fields (`hook_type`, `format`, `topic`, `pillar`, `engagement_score`, `why_it_worked`). Store the JSON in `posts.analysis`.  
7. **Detect Gaps** – Run a second Claude call (once per week) that receives the aggregated analysis and returns the intelligence brief JSON (top patterns, rising/fading topics, gaps, recommended mix).  
8. **Generate Drafts** – For each gap, call Claude with the cached voice profile and a prompt that specifies hook, format, and pillar. Persist drafts in a `drafts` table with status `pending_review`.  
9. **Deliver** – Push the brief and draft links to a Notion page and a Slack channel via n8n’s *Notion* and *Slack* nodes. Optionally expose a Next.js dashboard for client approvals.  

### Use Case 2 – Turn the Engine into a White‑Label SaaS Product  

1. **Parameterise Handles** – Store each client’s competitor list in a `clients` table; the n8n workflow reads the list dynamically.  
2. **Multi‑Tenant Supabase Schema** – Add a `client_id` foreign key to `posts`, `analysis`, and `drafts` tables; enforce row‑level security policies so each tenant only sees its own data.  
3. **Dynamic Voice Profiles** – When onboarding a new client, run a one‑off Claude call that analyses the client’s top 20 owned posts and writes a `/voice/profile_{client_id}.md` file. Store the file path in the `clients` table.  
4. **Billing Automation** – Integrate Stripe with n8n to create a subscription per client; on each successful payment, trigger the weekly pipeline for that client only.  
5. **Monitoring & Alerts** – Add n8n error‑handling branches that send a Slack alert if any Apify actor fails or if Claude returns an error status.

- **Basic prompting skill**: Crafting system prompts that enforce JSON output and brand voice.
