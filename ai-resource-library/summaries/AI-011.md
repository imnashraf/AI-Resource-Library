## 1. What This Resource Teaches  
This tutorial walks a developer through wiring Claude Code to the OpenAI Codex command‑line interface (CLI) so the two models can jointly audit, test, and simulate code. It explains how to install the Codex CLI, pull the community‑maintained *skill‑codex* plugin, embed a declarative hook inside a `CLAUDE.md` manifest, and validate the end‑to‑end flow with a simple audit request.  

Beyond the mechanical steps, the guide clarifies the architectural pattern: Claude Code performs high‑level reasoning and intent extraction, then automatically hands the same task to Codex, which excels at concrete execution‑path analysis. The dual‑model feedback loop produces a merged result that surfaces discrepancies and edge‑case failures that would otherwise slip through a single‑model review.  

## 2. Why It Matters  
Pairing two complementary LLMs reduces blind spots inherent to any single model, delivering more trustworthy code reviews without manual intervention. By automating the hand‑off via a `CLAUDE.md` hook, teams can embed continuous AI‑driven quality gates directly into their development workflow, cutting down on missed logical bugs and production regressions. The approach also leverages existing OpenAI API credits through the lightweight Codex CLI, keeping costs predictable while scaling across multiple projects.

## 4. Key Concepts & Principles  

- **Dual‑Model Review Loop**: Claude Code supplies contextual reasoning, while Codex evaluates concrete execution paths; their outputs are reconciled to highlight mismatches.  
- **Skill‑Based Plugin Architecture**: The *skill‑codex* repository provides a reusable plugin that tells Claude Code how to invoke the Codex CLI and interpret its JSON responses.  
- **Declarative Hook in `CLAUDE.md`**: A YAML‑style block defines trigger conditions (e.g., testing, auditing) and the sequence of actions (run Codex, compare results, flag discrepancies).  
- **Environment Variable Authentication**: The Codex CLI authenticates via an `OPENAI_API_KEY` exported in the shell, ensuring secure API calls without embedding secrets in code.  

## 5. Tools & Technologies Mentioned

- **Claude Code** – Anthropic’s code‑focused assistant that reads `CLAUDE.md` hooks, orchestrates tasks, and presents synthesized results.  
- **skill‑codex GitHub repo** – Community plugin that bridges Claude Code and the Codex CLI, containing the skill definition and runtime scripts.  
- **npm** – Package manager used to install the Codex CLI globally.

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Automated Test‑Run Auditing  
1. **Install Codex CLI**: `npm install -g @openai/codex`.  
2. **Expose API key**: `export OPENAI_API_KEY=sk-…` (add to `~/.bashrc` or `~/.zshrc` for persistence).  
3. **Clone plugin**: `git clone https://github.com/klaudworks/skill-codex.git`.  
4. **Copy plugin into project**: `cp -r skill-codex/plugins/skill-codex ./my-app/.claude-plugin/skill-codex`.  
5. **Add hook** to `CLAUDE.md` (trigger on “running tests”).  
6. **Run a test suite** inside Claude Code: ask it to “run the unit tests”. Claude executes the tests, then automatically invokes Codex to re‑evaluate the same code paths.  
7. **Review merged output**: discrepancies are highlighted; fix any issues flagged by Codex.  

### Use Case 2 – Pre‑Release Code Audit Pipeline  
1. Follow steps 1‑4 from Use Case 1 to set up the environment.  
2. Extend the `CLAUDE.md` hook to also fire on “auditing” events (e.g., before a merge).  
3. Integrate Claude Code into CI (e.g., via a script that launches Claude with the project directory).  
4. When a pull request is opened, the CI script triggers Claude to perform a high‑level audit, then Codex runs a parallel static‑analysis pass.  
5. The pipeline fails if the merged report contains any “medium‑severity” discrepancy, enforcing a quality gate before merge.
