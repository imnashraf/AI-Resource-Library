## 1. What This Resource Teaches  
This guide equips users with a toolbox of ten concrete tactics for stretching the token budget when working with Anthropic’s Claude models, especially the top‑tier “most capable” variants. It explains how the internal “effort dial” influences token consumption, why sending prompts in large batches is cheaper than turn‑by‑turn interaction, and how to deliberately cap the model’s output length.  

Beyond the mechanics, the article establishes a decision‑making framework that treats the most powerful Claude model as a planner/orchestrator while delegating the heavy‑lifting to cheaper sub‑models (e.g., Sonnet). By pairing this routing mindset with explicit effort‑level tags, goal‑oriented prompts, and persistent memory files, practitioners can keep usage within the limits of Pro, Max, Team, or Enterprise plans without sacrificing answer quality.  

## 2. Why It Matters  
Token consumption translates directly into cost and session‑time constraints on Claude‑based applications. Unchecked usage can exhaust the 5‑hour daily window or weekly quota, forcing users to pause work or upgrade plans. Implementing the recommended habits reduces waste by up to 50 % in many real‑world scenarios, allowing teams to allocate the expensive “high‑effort” model only to problems that truly need deep reasoning. This efficiency gain is especially critical for long‑running projects, automated agents, or any workflow that repeatedly calls Claude in a loop.

## 4. Key Concepts & Principles  

- **Effort‑Level Tuning**: Claude Code exposes a parameter that controls how much internal reasoning is applied. Lower levels (e.g., *low* or *medium*) are ideal for simple Q&A, while *high* or *xhigh* should be reserved for multi‑step or code‑review tasks. Explicitly stating the desired level in the prompt prevents the model from defaulting to maximum effort and burning extra tokens.  

- **Planner‑Executor Split**: Use the most capable model solely to outline a plan, then hand off each sub‑task to a cheaper model (commonly Sonnet). This “orchestrator” pattern leverages the strengths of each tier without paying the premium for full‑stack execution.  

- **Batch‑First Prompting**: Provide all necessary context—background, constraints, and desired output format—in a single message. Avoid incremental “drip‑feeding” because each new turn forces the model to re‑run its reasoning cycle, inflating token usage.  

- **Explicit Output Capping**: Attach a concrete word‑ or bullet‑count limit to every request (e.g., “max 250 words” or “no more than 5 bullet points”). Claude can otherwise generate up to 128 k tokens in one go, which is rarely needed and can quickly deplete the quota.  

## 5. Tools & Technologies Mentioned  

- **Claude (most capable models)** – The primary LLM used for high‑level planning and complex reasoning. Operates under a 2× usage multiplier on subscription plans.  
- **Sonnet** – A lower‑cost Claude variant suited for execution of routine content creation, standard coding, and short‑form research. Recommended for the bulk of day‑to‑day tasks.  
- **Claude Code** – The interface that exposes the effort‑level knob and supports agentic sub‑calls. Provides a status bar showing remaining session time and weekly budget.  
- **Memory Files (e.g., `DECISIONS.md`)** – Persistent markdown files that store decisions, constraints, and outcomes across sessions, reducing the need to resend the same context.  

## 6. Practical Use Cases & Workflows  

### Use Case 1 – Large‑Scale Code Refactor  
1. **Planning Prompt (high‑effort)**:  
   ```text
   Use the most capable model to outline a refactor plan for the repository at /src, targeting modularization and type safety. Return a bullet list of steps and required files.
   ```  
2. **Execution Loop (Sonnet, low‑effort)**:  
   - For each step, send a concise Sonnet prompt: “Apply step 1 to file X, output the diff only, keep under 200 words.”  
   - Append the diff to a `CHANGES.md` file.  
3. **Memory Update**: After each step, have Claude write a short entry to `DECISIONS.md` summarizing the rationale and any constraints.  
4. **Final Review**: Run a single high‑effort Claude call to verify that all success criteria are met, capping the output to 300 words.  

### Use Case 2 – Multi‑Stage Market Research Report  
1. **Context Batch**: Gather raw articles, data tables, and research questions into a single prompt. Include a directive: “Produce a 5‑section report, each section ≤ 150 words, bullet‑point summary only.”  
2. **Effort Setting**: Tag the request with `medium` effort because the task is summarisation, not deep reasoning.  
3. **Output Cap**: Explicitly request “no more than 750 words total.”  
4. **Memory File**: Store the final report in `REPORT.md` and log key insights in `DECISIONS.md` for future reference.
